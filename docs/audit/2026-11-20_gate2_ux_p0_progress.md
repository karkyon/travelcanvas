## 5. #163 のレビューで直したこと(2026-11-21)

追加した予定を選んで開く(§4)の作りを、store の動きまで追って確かめた。

| 点 | 確かめた結果 | 対応 |
|---|---|---|
| 増えた予定の ID | `addScheduleItem`・`addScheduleItemFromCandidate` は作成の後に `loadPlan` で読み直すので、比べて増えた予定は**サーバーの予定の ID**(場所・候補の ID ではない)。通信できず端末に溜めた時だけ仮の ID(同期の後に旅程を読み直すと、その ID は無くなり選択が外れるだけ) | 変えない |
| 追加の失敗(手入力の経路) | `addScheduleItem` は失敗しても例外を投げない(store が「失敗」を知らせて元に戻す)。そのため**失敗でも「追加しました」と出て、窓が閉じて旅程へ移っていた**(以前から) | 増えた予定が無い時は成功と言わず、窓を残す(もう一度押せる) |
| 別の日・全日程を見ていた時 | 同じ旅行を読み直すと見ている日を保つ(`loadPlan` の `keepDay`)。2 日目を見ていると、1 日目に入れた予定を選んでも**旅程にも地図にも出なかった** | 予定のある日を開き、日別の表示に戻してから選ぶ |
| 印の後始末 | 履歴の `state` に印が残り、再読み込み・戻る操作で選び直していた | 選んだ後(または旅行に無い印の時)に `state` を消す。消す時の移動先は固定の `/planner/{planId}`(`navigationSafety` の規則)。この画面の URL の検索部分は使っていない |
| 古い・別の旅行の印 | 開いている旅行(`planId` と `currentPlan.id` が一致)に無い予定の印は何も選ばない | 試験で固定 |
| 二度押し | 追加の間は旅行のボタンが押せない(`isAddingSpot`。以前から) | 変えない |
| 控えの案(Plan B)を開いている時 | 旅程はその案の日を出すので、選んだ予定が見えないことがある | 未対応(検索から追加した直後に控えの案が開いている状況は通常無い) |

試験: `PlannerPage.test.tsx` に 5 件(手入力の追加の失敗・候補からの追加の成功と失敗・別の日を見ていた時・旅行に無い印)。修正を外すと 3 件が落ちることを確かめた。確認は vitest・eslint・型検査まで。**実機・利用者の操作での確認は無い。**

## 9. 旅程の地図の表示範囲を保つ(2026-11-21 夜。main `3c4a3c4` 起点)

| 点 | 内容 |
|---|---|
| 以前 | 旅程の地図は、開くたび・地図を大きくするたびに、予定の印に合わせて範囲を決め直していた。利用者が動かした中心・拡大は、全体の検索などへ移って戻ると失われた |
| 変更 | 旅行と日ごとに、利用者が動かした中心と拡大を覚える(`components/planner/mapViewMemory.ts`)。同じ旅行・同じ日・**同じ印**なら、戻った時と地図を大きくした時に、その範囲のまま出す |
| 守り | 印が変わった時(予定を足した・消した・場所を直した)は覚えた範囲を使わず、印に合わせる(足した予定が範囲の外に隠れないように。#163 の選ぶ動きもそのまま)。別の日・別の旅行も印に合わせる |
| 個人の情報 | 画面のメモリだけに持つ(端末には書かない。再読み込みで消える)。ログアウトで消す |
| 試験 | `PlanMap.view.test.tsx`: 戻ると覚えた範囲で出す(変更を外すと落ちることを確かめた) / 印・日・旅行が変わると印に合わせる / ログアウトの後は使わない。frontend の vitest は 271 ファイル・1,546 件が通過。eslint・型検査は 0 件 |
