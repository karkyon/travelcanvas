## 3. SECURITY-TRACE の試験(`test_gate_receipt` の失敗と 4 件の飛ばし)

SECURITY-TRACE.md が参照する backend の試験 54 ファイルを、CI と同じ条件で手元で流した。条件は PostgreSQL 16・Redis 7・`TC_REQUIRE_REDIS=1`・Alembic head、**tesseract-ocr(jpn・eng)あり**。

| 実行 | 結果 |
|---|---|
| 以前(11-20。手元に tesseract・Redis 無し) | 581 passed・4 skipped・1 failed |
| 今回(CI と同じ条件) | **586 passed・0 skipped・0 failed** |

**失敗した 1 件** `tests/test_gate_receipt.py::test_AI_は同意がある時だけで_失敗しても_500_にしない`(82 行目)
- 期待は 422(`nothing_extracted` か `ocr_unavailable`)。実際は 503。
- 原因: 手元に tesseract が無かった。OCR が使えない時、レシートの読み取りの API は 503 を返す。試験は OCR がある前提で書かれている。
- tesseract を入れると 11 件すべて通過した。コードの不具合ではない。

**飛ばされていた試験** `tests/test_gate_receipt.py` の 3 件。理由はどれも「tesseract が無い」(`rx.ocr_available()` による skipif)。
- `test_傾きとぼけのある画像を読む[receipt_jp_photo.jpg-1260-JPY]`
- `test_傾きとぼけのある画像を読む[receipt_en_photo.jpg-10.59-USD]`
- `test_API_候補を返すだけで支出は作らない`

4 件目は Redis に届かない時に飛ばされる試験(§3.1)。

**CI での実行:** CI の backend のジョブは、試験の前に `tesseract-ocr tesseract-ocr-jpn tesseract-ocr-eng` を入れる(`ci.yml` 212 行目)。同じ条件の手元の実行では 11 件とも通過した。run #823 の backend は success で、pytest の段は失敗で止まる作りになっている。
ただし、ジョブのログの本体(各試験の PASSED の行)は、この作業環境からは取得先(Azure blob)がプロキシで拒否されて読めなかった。API で読める末尾は PostgreSQL のサービスのログだけだった。そのため、**#823 のログの中で該当の行を直接は確かめていない。**

### 3.1 Redis が無い時に飛ばされる試験

Redis に届かない状態で同じ 54 ファイルを流し直した結果は 585 passed・1 skipped。飛ばされたのは次の 1 件。
- `tests/test_gate_c1_collaboration.py::test_presence_in_redis_is_shared_and_expires`(190 行目。理由「Redis に届かない環境」)

以前の 4 件の内訳は、tesseract の 3 件とこの 1 件。以前の実行の記録にはファイル名が残っていないので、条件をそろえて再現して確かめた。

CI には「Redis を使う試験の実行の確認 (ブロッキング)」の段がある(`ci.yml` 273 行目)。理由に Redis を含む飛ばしが 1 件でもあれば失敗する作り(`check_required_tests.py --forbid-skip-reason Redis`)。run #823 でこの段は success だった。**したがって CI ではこの試験は飛ばされずに実行されている。**
