## 0. 共通の決まり

| 項目 | 決まり |

| 環境 | A: CI(模擬の provider・Playwright の画面の大きさの模擬)/ B: GCP 開発環境 travelcanvas-dev(Tailscale 経由・実データの写し)/ C: 実機(iPhone Safari・Android Chrome・iPad 縦横・PC Chrome) |
| 外部の提供元 | **stub/mock ケース**(CI・開発で鍵なし)と **実サービスケース**(鍵・契約の後。課金のあるものは利用者の承認・低額の上限・計測が前提)を分ける。実サービスケースは承認が無ければ実施しない |
| 役割 | 未登録(ゲスト)/ 所有者 / 編集者 / 投票者 / 閲覧者 / 共有リンクの閲覧者(未登録)/ 運用管理者 |

| 判定 | 期待値をすべて満たす=合格。実施できない(鍵・実機・本番が無い)=「未実施」と書き、合格にしない |

## S1 ゲスト・新規旅行: 相談 → 発見/検索 → 候補保存 → 旅程化 → 共有

- **開始条件:** 未登録のブラウザ(Cookie・端末の保存なし)。
- **役割:** 未登録 → ゲスト所有者 → 登録利用者(昇格)、共有の閲覧者(別のブラウザ)、編集者・投票者(招待)。
- **データ:** 行き先「京都」2 泊 3 日、予定 5 件(時刻未定・場所未定を含む)、候補 3 件(URL・検索・手入力)。
- **手順と期待値:**
  1. LP から開始 → 説明なしで 3 分以内に旅行と予定 1 件を保存(FR-043・FR-001。DOC-02 FR-001 は 60 秒)。保存の状態が見える。
  2. 旅行相談で条件を入れる(FR-059: 外部 API の枠が見え、枠の超過で止まる)。
  3. 検索・URL から候補を保存(FR-007・FR-009)。出典・取得時刻が残る。同じ場所は重複の候補として示す(自動で消さない)。
  4. 候補を旅程へ置く → 場所が 1 つの ID になる(FR-008)。並べ替えて影響を確かめ Undo(FR-005)。
  5. 旅行の基本(期間・タイムゾーン)を直す(FR-004)。複製で別日の案を作る(FR-047。予約番号は複製されない)。
  6. 登録して昇格(FR-002・FR-003)。旅行・写真・共有設定を失わない。
  7. 編集者・投票者を招待(FR-021)、同時に編集して競合を表示(FR-020)、候補に投票・合意(FR-022)、コメント・通知(FR-024)、秘匿の条件(FR-023)。
  8. 共有リンク(期限・PIN・項目)を作り、別のブラウザで開く(FR-044・FR-045)。予約番号・QR・位置が見えない。停止後は開けない。
- **失敗・境界:** 保存中の通信断で入力を失わない / 共有を 2 回作っても漏れない / 閲覧者は編集できない / 期限切れのリンク / 相談の提供元の timeout。
- **画面遷移:** `/` → `/trip-consult` → `/planner/:id` → `/planner/:id/candidates` → `/planner/:id/places/:placeId` → `/guest/upgrade` → `/share/:id` → `/s/:token`。
- **実機/API:** 実機 C で 1〜3・8 を実施。相談の AI・Google 検索は実サービスケース(承認後)。

## S2 予約: メール/手入力取込 → 確認/分割 → チケット/QR → オフライン表示

- **開始条件:** S1 の登録利用者の旅行。オフラインの端末の鍵を登録済み。
- **役割:** 所有者、閲覧者(チケットの権限なし)。
- **データ:** ホテル 1・新幹線 2(1 通のメールに 2 予約)・食事 1。QR と Code 128 を 1 つずつ。PDF の確認書 1。
- **手順と期待値:**
  1. 予約メールの文を貼る/転送アドレス/Gmail(読み取りだけ・押した時だけ)で取り込む(FR-011)。候補は原本と並べ、確定するまで予約にならない。1 通から 2 予約に分ける。
  2. 予約を確かめ予定に紐付ける(FR-010)。取消期限が見える。
  3. 確認書の PDF を文書に入れる(FR-013。種類・容量の検査、本人だけの既定)。
  4. チケット・QR を全画面で出す(FR-012)。閲覧者には payload が API にも出ない。
  5. オフラインのパックを作り、機内モードで今日の予定・宿の住所・予約番号・QR・緊急の連絡先を開く(FR-032・FR-048。AC-05)。最終同期の時刻が見える。
- **失敗・境界:** 同じメールの再取込で予約が二重にならない / 誤った取込の取り消し・再処理で元の予約が消えない / Gmail の権限の拒否・取消 / 鍵の期限切れの端末はパックを開けない / 削除・ログアウトの後にパックが消える(次の通信の時)。
- **画面遷移:** `/planner/:id/imports` → `/planner/:id/reservations` → `/planner/:id/documents` → `/planner/:id/today`(オフライン)。
- **実機/API:** 5 は実機 C 必須(sw.js の登録・iPhone のホーム画面追加を含む)。Gmail・受信サービスは実サービスケース(OAuth クライアントの設定後)。

## S3 旅行前: 日付/現地時間 → 移動 → 営業時間/天気 → 持ち物/予約 → 実行可能性

- **開始条件:** S2 の旅行(予約あり)。
- **役割:** 所有者・編集者。
- **データ:** 海外 1 都市を含む日程(タイムゾーンが違う)、営業時間外の店 1、移動の足りない区間 1、予算 3 費目。
- **手順と期待値:**
  1. 移動区間を足し、手段・所要を入れる(FR-014)。経路を比べる(FR-015。取れない時は手で)。
  2. 制約(終電・予算・秘匿の条件)を入れ(FR-016)、実行可能性で営業時間外・移動不足を根拠つきで出す(FR-017。AC-03。「問題なし」と誤らない)。
  3. 最適化で固定の予約を動かさず順を変え、差分を見て適用・Undo(FR-018。AC-04)。
  4. 持ち物・準備(FR-025・FR-026)、予算・為替(FR-027)。
  5. しおり・PDF・画像・カレンダー/地図の出力(FR-034・FR-035・FR-036・FR-046)。機密は既定で除かれ、公開ページは noindex。
  6. 料金の画面で現在のクラスと枠を確かめる(FR-058。Stripe はテストモードだけ)。
- **失敗・境界:** DST・日付変更線の便 / 2 人が同時に最適化を適用(base revision の不一致で拒否)/ 為替が取れない時に日時つきの最後の値 / 出力中の旅程の更新。
- **画面遷移:** `/planner/:id/segments` → `/planner/:id/route-options` → `/planner/:id/constraints` → `/optimization` → `/planner/:id/preparation` → `/planner/:id/expenses` → `/planner/:id/booklet` → `/planner/:id/exports` → `/settings/billing`。
- **実機/API:** 経路・時刻表(駅すぱあと)・Stripe は実サービスケース。PDF の字体・地図の画像は配備先で確かめる。

## S4 旅行当日: NOW/NEXT → 出発判断 → 地図/外部ナビ → 到着/印 → 写真/記録 → 次予定

- **開始条件:** 旅行の 1 日目の朝(端末の時刻と旅行のタイムゾーン)。位置の記録は OFF(既定)と ON の 2 通り。
- **役割:** 所有者・同行者(到着の予定の共有)。
- **データ:** S3 の旅程。登録した移動・概算の移動・手入力の移動が混ざる日。
- **手順と期待値:**
  1. 今日の画面に NOW・NEXT・出発まで・必要なチケット(FR-006・FR-029)。移動の出どころ(実時刻/手入力/登録/概算/不明)が見える。
  2. 出発の判断 → 「外の地図で案内」で外のアプリへ(道順はアプリ内で描かない。地図の線は「直線の目安」、位置の記録 OFF の時は「足跡」と出ない)。
  3. 到着の印・写真・ひとこと(FR-037 の記録)。位置の記録 ON の時の軌跡と訪問の判定(FR-038・FR-049・FR-050・FR-055・FR-056)。端末内のみの時に生の点を送らない。
  4. オフラインで予定を直し、通信が戻って一度だけ同期(FR-033。AC-08: 2 端末の競合を黙って消さない)。
  5. 同行者に到着の予定を共有(位置は送らない)、端末の通知を受ける(Push の許可・拒否の両方)。
  6. **スポットモード(FR-060):** 自由に歩くエリアに近づくと(位置の許可がある時)・時間になると予定の画面で切り替えを勧める → 「切り替える」で
     スポットモード → ジャンルで絞る・候補を選ぶ(歩く時間・方角・道順の目安・地図アプリで開く)→ 「着いた」→ 次どこ？(気分の札)→
     周りを探す(トイレ等。結果を「候補に」)→ 方角で見る → 「予定」に戻る。戻り始めの時刻が集合に間に合うか。機内モードで端末に保存した
     エリアが出るか。タブレット横で地図と欄が左右に並ぶか。
  7. **今度行きたい(FR-062):** 歩いている途中で上の帯・当日の画面の ♡ → 今いる所の近くの候補を押す(2 タップ)。圏外(機内モード)で
     残した分が、つながった時に 1 件だけ入るか。同じ店をもう一度 ♡ すると「もう残してあります」。夜の「次の旅の候補に」で
     「今度行きたい」を選ぶ。行きたい場所の「近くに来たら知らせる」を入れた店の近く(300m)で、当日の画面に 1 回だけ知らせが出るか。
  8. **日帰り(FR-061):** 帰りの日の寄り道として、または別の日帰りの旅行で、ルートの画面を開き、ジャンル・幅を変え、寄り道を
     「予定に入れる」→ 家に着く見込みが変わる。高速と下道の比べ(Google の鍵が確認済みの時は線と料金、無い時は OSRM か直線の札)。
- **失敗・境界:** 過去/未来の日を見ている間に自動で移らない / エリアの日でなければ残り時間を出さない / 位置の許可が無い時に勧めの判定で許可を求めない / 夜行便 / 端末の時計のずれ / 通知の拒否・購読の失効 / 位置の許可の途中の撤回。
- **画面遷移:** `/planner/:id/today`(子画面: 地図・移動・宿へ帰る・寄り道・旅帖・同行者・お助け)→ `/planner/:id/track` → `/planner/:id/visits` → `/planner/:id/sync`。
- **実機/API:** **実機 C 必須**(親指の届く範囲・固定帯の占有・200% の文字・読み上げ・機内モード・電池)。乗換の実時刻(ODPT)は実サービスケース。

## S5 変更: 雨/遅延/休業 → 根拠/影響 → プランB/変更 → 共有の競合/通知

- **開始条件:** S4 の当日。雨の時間帯・遅延・休業を 1 件ずつ起こす(手入力の alert か、天気の取得)。
- **役割:** 所有者・編集者・閲覧者。
- **手順と期待値:**
  1. 外部の状況(天気・警報・遅延・休業)が出どころと取得時刻つきで出る(FR-030)。取れない時に最後の値を今の値に見せない。
  2. 影響を見て再計画の案 A/B(固定の予約を守る・費用差・遅延差・失う予定)(FR-031。AC-06)。承認の前に共有の旅程を変えない。
  3. プランB(日ごとの案)に切り替え、切り替えの記録が残る(FR-019)。
  4. 共有の相手に差分の通知、同時の編集の競合の表示。
- **失敗・境界:** 2 人が別の案を同時に採用 / 通信断の間の切り替え / 古い通知の抑止。
- **画面遷移:** `/planner/:id/today` → `/planner/:id/alerts` → `/planner/:id/replans/:replanId` → `/planner/:id`(プランB)。
- **実機/API:** 気象庁・ODPT・休業の提供元は実サービスケース。CI は模擬の alert。

## S6 旅行後: 実績/費用/立替 → 写真/公開範囲 → Export/削除 → Atlas

- **開始条件:** 旅行の終了後。S4 の記録あり。
- **役割:** 所有者・同行者・公開ページの閲覧者(未登録)。
- **手順と期待値:**
  1. 予定と実績を比べる(FR-054)、達成の指標(FR-053。数値は隠せる)。
  2. 費用の実績・立替・精算(FR-028)。
  3. 写真・旅行記の下書き(作り方の表示: AI は使わない)→ 公開前の検査(顔・同行者・位置・予約)→ 公開・停止(FR-037)。
  4. 誤った訪問を訂正・除外、守る範囲(FR-051)。Atlas に反映(FR-052)。次の旅行への提案(FR-057。適用するまで変えない)。
  4b. 旅の記録の「また行きたい」(FR-062): 行った場所に ♡・このエリアごと残す・行けなかった場所をまとめて今度行きたいへ(候補箱は残る)。
      行きたい場所の札(今度・また・エリア)と残した元が出るか。「ここから日帰り」で日帰り(FR-061)の作成が開くか。
  4c. SNS の下書きとリール(FR-063): 旅の記録の「SNS の下書き・リールを作る」→ 写真を選ぶ → 文(自宅の近く・時刻・同行者の名前が
      入らない)→ TikTok で 30 秒のリールを端末で作る → 保存・共有(TikTok のアプリで読み込める。アプリは投稿しない)。
  5. データの書き出し・削除(FR-039)。共有が即失効し、削除の後に検索・保存・cache に残らない。
- **失敗・境界:** 公開の停止の後に開けない / 削除の取り消しの期限 / 他人の記録を含める時の範囲。
- **画面遷移:** `/planner/:id/journey` → `/planner/:id/expenses` → `/planner/:id/memories` → `/journal/:token` → `/planner/:id/visits` → `/atlas` → `/planner/:id/memory-replan` → `/settings/data`。
- **実機/API:** 写真の投稿・地図は実機 C。顔の検査(Cloud Vision)・地域の判定(国土地理院・Nominatim)は実サービスケース。
