# ADR: 共同編集(準リアルタイム)と秘匿プロフィール(Gate C1)

- 状態: 採用(2026-10-19)
- 対象: FR-020 共同編集(DOC-02)・FR-023 秘匿プロフィール・制約(DOC-02)
- 関連: Gate #29(revision/If-Match)、L2(制約・秘匿制約)、L3(実行可能性検証)、P11(オフライン同期の競合)、S3(Redis の共有)

## 1. FR-020 共同編集

### 決めたこと

- **準リアルタイム(問い合わせ)**: 旅行を開いている端末は `POST /plans/{id}/presence` で数秒ごとに知らせる。応答は
  「同じ旅行を開いている人(役割・編集中の予定)」と「画面が知っている版より後の変更(誰が・どの予定を・何を)」。
  間隔は backend が決める(他の人がいれば5秒、ひとりなら15秒)。WebSocket は使わない(下の理由)。
- **短い間だけの情報は DB に持たない**: 開いている端末は Redis(回数制限と同じ接続・名前空間。S3)に旅行ごとのハッシュで置き、
  40秒知らせが無い端末は「いない」。Redis に届かない時はプロセス内で続ける(1つのプロセスの中でだけ見える)。
  持つのは 利用者の ID・端末の印(画面が作る乱数)・編集中の予定の ID・時刻だけ。
- **他の人の変更で画面を勝手に書き換えない**: 「ほかの人が旅程を変更しました」と「最新を読み込む」を示す(編集中の入力を失わない)。
- **同時に編集**: 先に保存した方が通り、古い版の保存は 409(Gate #29 の If-Match)。画面は入力を残したまま、
  編集を始めた時の内容・自分の入力・読み直した最新の内容を項目ごとに比べ、「ほかの人の値」を示す。
  「自分の変更を最新の内容に重ねて保存」は自分が変えた項目だけを最新に重ねる(相手が変えた項目は残る)。
  相手が予定を消していたら、そう示して閉じる。黙って上書きしない。
- 名前は利用者名(メールアドレスは出さない。ゲストは「ゲスト」)。旅行から外れた人・関係のない人は数えない/使えない。

### WebSocket を使わない理由

- 本番の構成(nginx・uvicorn の複数プロセス)で、接続の維持・認証の更新・切断からの回復・プロセス間の配信(Redis の pub/sub)を
  新たに運用する必要がある。旅行の共同編集は同時に開く人が数人で、数秒の遅れは許容できる(DOC-02「リアルタイムまたは準リアルタイム」)。
- 問い合わせは既存の認証・認可・回数制限・監視(ルートの型別)・ログの検査をそのまま通る。

### 未達(INTEGRATED(部分))

- カーソル(入力位置)の表示、変更の即時の配信(WebSocket)、項目単位の自動の合わせ(今は利用者が選ぶ)。

## 2. FR-023 秘匿プロフィール

### 決めたこと

- 旅行をまたいで使う非公開の条件を、利用者ごとに **1つの暗号文だけ**で持つ(`user_private_profiles.items_ciphertext`、Fernet)。
  題名(「朝はゆっくりしたい」等)も値も平文の列に置かない。運用管理者の画面・API にも出さない。監査には件数だけを残す。
- 種類は **判定できるものだけ**: 開始が早すぎない・終わりが遅すぎない・1日の移動の上限・食事の間隔・旅行の予算の上限・
  避けたいこと(予定の名前・説明の語)・避けたい移動手段。健康・宗教・食事の事情は「避けたいこと」の語で表す
  (名前は本人だけに見える)。判定できない自由記述の条件は作らない(FR-017「検証不能を問題なしにしない」)。
- 旅行ごとに「この旅行に適用する」を選ぶ(`private_profile_links`)。適用すると、項目ごとに **本人の秘匿制約**(L2 の
  constraints、`profile_item_id` で対応付け)を作り、プロフィールを変えるたびに作り直す。判定(L3・L4)は秘匿制約の
  既存の扱いのまま: 他の参加者には「秘匿制約を満たしていません(内容は作成者本人にだけ表示されます)」だけ。
- プロフィールから作った制約は、制約の画面からは変えない(409)。設定で変えるか、適用をやめる。
- 書き出し: アカウントの書き出しに本人の項目(復号)、旅行の書き出しに本人の適用だけ。アカウントの削除で全部消す。

### migration

`a9d4e7c2f8b3`: `user_private_profiles`・`private_profile_links`(plan_id は ON DELETE CASCADE)、`constraints.profile_item_id`。
downgrade はプロフィールから作った秘匿制約を削除済みにしてから列・表を消す。

## 追記: 即時の通知(Gate G2、2026-10-21)

- 問い合わせ(ポーリング)に加えて、`GET /plans/{id}/events/stream`(Server-Sent Events。サーバーから画面へ一方向に送り続ける
  HTTP の仕組み)で「版が上がった(revision)」「開いている人・編集中の予定が変わった(presence)」をその場で知らせる。
  画面は知らせを受けたらすぐ `POST /presence` で中身を取る(送る内容は従来の問い合わせと同じ。通知には予定の内容を載せない)。
- WebSocket ではなく SSE にした理由: 片方向で足りる・HTTP のまま認証(Authorization)・CORS・CSP・回数制限がそのまま使える・
  途中の機器を選ばない。EventSource はヘッダーを付けられないため、画面は fetch で読む(`frontend/src/utils/sse.ts`)。
- 接続は45秒で閉じ、`Last-Event-ID`(知っている版)でつなぎ直す。旅行を見られなくなると `access_lost` で閉じる。
  1人あたり4本まで。つながっている間の問い合わせの間隔は20秒(開いていることを知らせ続けるため0にしない)。
- 文字単位の同時編集(CRDT)は対象外。同じ予定の同時の保存は従来どおり版の競合(409)で止め、黙って上書きしない。
