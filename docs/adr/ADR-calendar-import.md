# ADR: カレンダー(ICS)の取込(Gate P8 / FR-036)

- 状態: 採用
- 対象: FR-036「外部カレンダー・地図との連携。外部更新の取込は差分確認後に適用する」、DOC-04 SC-27
- 前提: Gate P5(ICS書き出し、UID `event-<id>@travelcanvas.app`、SEQUENCE=本案revision)

## 1. 決定

1. **ファイル取込のみ**(OAuth等による外部カレンダーとの常時同期は対象外)。利用者が他のカレンダーから書き出した
   ICSファイル(1MB・500件まで、UTF-8)を選ぶ。
2. **2段階**: `POST /plans/{id}/calendar-import/preview` は解析と本案との照合だけ(DB不変)。
   `POST /plans/{id}/calendar-import/apply` は画面で選ばれた案だけを、本案のrevision(If-Match)付きで適用する。
   適用は1つの変更セット(source=`import`)で記録し、本案の「元に戻す」で全て戻る(共通不変条件4)。
3. **取り込む項目**: 予定名・日付・開始時刻・終日・場所(LOCATION→住所欄)。DESCRIPTIONは取り込まない
   (会議URL・パスコード等の持込を避ける)。時刻付きの予定は本案の時刻帯(最初の日程の`timezone_id`)の現地時刻へ変換し、
   TZ無しの時刻(浮動時刻)はそのまま現地時刻として扱う。
4. **照合**: TravelCanvasが書き出した予定(UIDが自分の形式で、本案に存在)は「同じ予定の変更」として前後差分を出す。
   住所を含めずに書き出したICSで住所を消さない。その他の予定は「追加」。
5. **取り込まない予定と理由**: 繰り返し(RRULE/RDATE)・取消済み(STATUS:CANCELLED)・本案と同じ・本案で確定済み(locked)・
   同じ日時・同名の予定が既にある(重複)・その日の日程が無い(「日程を追加して取り込む」を選べば日程を作る)。
6. **権限・監査**: editor以上。監査は件数の要約だけで、ファイル内容・予定名は記録しない。
7. 適用時は全件を先に検査し、一部だけ適用された状態を残さない(確定済み・存在しない予定は409、日程なしは422)。

## 2. 却下した案

- 外部カレンダーAPIとの双方向同期: 認可・トークン保管・競合解決の範囲が大きく、本Gateでは扱わない。
- 繰り返し予定の展開: 旅行期間に限った展開でも例外日(EXDATE)・RECURRENCE-IDの扱いが要り、誤取込の危険が大きい。

## 3. 未実装(次Gate以降)

- 外部カレンダーとの常時同期(OAuth)、予定の削除の取込(ICSから消えた予定を本案から消す)。
- 予定の終了時刻・移動・予約の取込。
