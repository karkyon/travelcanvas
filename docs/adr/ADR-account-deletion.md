# ADR: アカウントの削除と同意の撤回(Gate P9 / FR-039)

- 状態: 採用
- 対象: FR-039「旅行単位・アカウント単位のエクスポート、訂正、削除、同意撤回」のうちアカウント単位の削除と同意の撤回、
  DOC-11 §15(Deletion: workflow・共有即失効・backup期限説明 / Consent withdrawal: AI・位置・分析・メールを目的別停止)、
  DOC-04 SC-29
- 前提: Gate B-012(旅行の論理削除→猶予→完全削除)、Gate P6(エクスポート・保持期間の説明)

## 1. API

| メソッド | パス | 内容 |
|---|---|---|
| GET | /privacy/account-deletion | 削除で何が起きるかの説明(DB不変)。所有する旅行と参加者数、参加している旅行で消えるもの・残るもの、猶予日数、保持期間 |
| POST | /privacy/account-deletion | `{confirmation: "退会する", password?}`。登録ユーザーはパスワード必須(違えば403 `reauth_failed`、監査に記録)。確認の文字が違えば422 `confirmation_mismatch`。1時間5回まで(429)。管理者は403 `admin_account` |
| GET | /privacy/consents | 目的別の同意(ai_processing / location / analytics / marketing_email) |
| PUT | /privacy/consents | `{consents: {目的: bool}}`。不明な目的は422。監査には変化した目的と新しい値だけを記録 |

ゲストも利用できる(ゲストはパスワードが無いため確認の文字だけ)。

## 2. 削除で行うこと(取り消せない)

| 対象 | 扱い |
|---|---|
| 所有する旅行 | B-012の論理削除。共有リンクは即時失効、参加者もすぐ見られない。猶予日数後に既存の完全削除バッチで子データ・文書ファイルごと削除 |
| 参加している旅行への参加 | 共同編集者の行を削除(チケット担当・参加者の割当は外す)。本人宛ての招待(メールアドレスを含む)も削除 |
| 参加している旅行の本人だけの情報 | 個人の持ち物・秘匿の条件・個人予算を削除。本人がアップロードした文書は論理削除し実ファイルを即時削除(失敗時は既存の文書purgeで再試行)。持ち物・準備タスクの担当は外す |
| 同行者の記録 | コメント・支出・精算・投票・変更履歴は残す(他の参加者の精算や合意の記録が壊れるため)。名前は「退会済み-xxxxxxxx」と表示される。削除前の説明で件数を示し、残したくないものは事前に消すよう案内する |
| 本人だけのデータ | セッション(IP・端末情報を含む)・通知・お気に入り・訪問記録・冪等性記録を削除 |
| アカウント行 | 外部キーで多数の表から参照されるため行は残し、メール・パスワード・設定を消して無効化、名前を仮名にする。同じメールで新しく登録できる |
| 端末 | 完了画面でこの端末のオフラインパックとログイン状態を消す(DOC-11 §8)。他の端末のオフラインパックは次回通信時にトークンが拒否されるが、端末内の暗号化データの遠隔消去は保証しない |

- 削除後は同じアクセストークン・ゲストトークンを受け付けない。ゲストトークンは従来DBを参照していなかったため、
  無効化されたゲストの行があれば401にする検査を `app/core/auth.py` に追加した。
- 監査には削除の事実と件数だけを記録し、題名・メールアドレスは記録しない。監査ログ・バックアップの保持は
  GET /privacy/retention の説明に従う。

## 3. 同意の台帳

- `users.preferences["privacy_consents"]` に目的ごとの `{granted, updated_at}` を保存する(migrationなし)。既定は全て「同意しない」。
- **現時点でこれらの目的の処理を行う機能は無い**(画面にも「現在、この目的の処理を行う機能はありません」と表示する)。
  今後その処理を追加する時は、処理の前に `app.services.consents.has_consent(user, purpose)` を確認し、
  撤回後は新しい処理を行わないこと。

## 4. 却下した案・未実装

- 猶予期間つきのアカウント削除(期間中は取り消し可能): ログイン不可の状態での取り消し導線と、猶予中の共同旅行の扱いが必要になるため見送り。
  旅行データは論理削除の猶予(B-012)で保護される。
- 所有者の移譲: 参加者のいる旅行を残したい場合の所有者移譲(SC-18)は未実装。説明画面で参加者数を示して注意を促す。
- 他の参加者が受け取った通知本文に残る名前、旧来の`travels`表・登録した`spots`は対象外(残件)。
- 訂正(Correction)は既存のプロフィール編集(PUT /auth/me)で行う。出典・検証・履歴つきの訂正は未実装。
