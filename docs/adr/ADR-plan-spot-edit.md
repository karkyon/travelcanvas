# ADR: 旅程のスポットの編集(Gate PlanSpotEdit)

- 日付: 2026-11-06
- 状態: 採用(PR のレビュー待ち。omega-dev2 の UAT は未実施)
- 起点: 利用者の課題一覧(TravelCanvas 課題.xlsx)#3「PLAN · 旅程を組み立てる / 旅程・工程タイムライン / 各スポットの編集機能」①〜⑬

## 決めたこと

### ① 並べ替えは「スポットだけを入れ替える」

- ドラッグ・↑↓で並べ替えた時、**時刻(開始・終了・終日)と移動区間(移動手段・出発/到着・所要時間・費用など)は並びの位置に残し、場所(予定)だけを入れ替える**。
- 新しい API `POST /plans/{plan_id}/days/{day_id}/reorder`(`order`・`keep_slots`=既定 true・If-Match)で、1 つの変更(ChangeSet)として行う。
  1 回の「元に戻す」で予定と区間の全部が戻る。画面の「並べ替えの影響」の「元に戻す」は、同じ規則で元の並びへ並べ直す(時刻・移動手段も元の位置へ戻る)。
- 確定(locked)の予定の位置は変えない(409 `locked_event`)。並びの過不足は 400 `order_mismatch`。
- 移動区間の端の付け替えは「元の位置 i の予定 → 新しい位置 i の予定」。前の日・次の日の予定とつながる区間も同じ規則で付け替える
  (例: 1 日の最後の予定から翌日へ向かう区間は、入れ替えた後もその日の最後の予定から出る)。
- 以前の「1 件ずつ移動の API を呼ぶ」並べ替え(`moveEvent` の連続)は、日の間の移動・オフラインの同期のために残す。
- 保存する前の案(ReorderPreview)も同じ規則で見せる(`plannerModel.keepSlots`)。
- 以前のドラッグの「落とす場所」は予定の間の高さ 8px の透明な帯だけで、予定の上では既定の処理(禁止の印)のまま落とせなかった。予定の行そのものを落とす場所にし、上半分なら前・下半分なら後ろへ入れる(線で示す)。

### ⑤⑨ 場所の情報(住所・電話番号・種類)を自動で集める — 法令・規約の確認

| 観点 | 確認した内容 | 対応 |
|---|---|---|
| 提供元 | 既に利用している OpenStreetMap の Nominatim(無料・鍵なし)だけを使う。Google Places 等の有料の提供元は使わない | 追加の請求なし。`free_usage` に回数を記録(結果・入力は残さない) |
| Nominatim Usage Policy | 1 秒に 1 回まで・送り手が分かる User-Agent・一括の取得や自動の繰り返しをしない・結果を保存して使い回す | 押した時(予定を足す時に場所を選んだ時)の 1 回だけ送る。プロセスの中で 1.1 秒の間を空ける。同じ問い合わせは 1 時間は保存した結果を使う。1 人 10 分 30 回まで |
| データの利用条件(ODbL 1.0) | 結果を見せる所に「© OpenStreetMap contributors」と ODbL を示す。利用者の旅程へ 1 件の住所・電話番号を写すのは、データベースの実質的な部分の抽出ではない | 候補の欄と、予定の追加の知らせに出典と ODbL を出し、著作権の案内(openstreetmap.org/copyright)へのリンクを付ける |
| 個人情報 | 送るのは場所の名前と位置(予定の座標)だけ。利用者の名前・旅程の他の内容は送らない | 名前は 200 文字、座標は数値に限る |
| 正確さ | OSM の情報は古い・違うことがある | 入れる前に候補として見せ、利用者が「入れる」を押した時だけ入れる(予定の追加では空の欄にだけ入れ、確かめるよう知らせる) |

- 電話番号は予定ごとの値として `travel_events.phone`(String 40・NULL 可)に持つ(migration `a7d2c9e4f1b8`。列の追加だけ・downgrade で列を消す)。
  電話番号は場所を特定できるため、同行者に住所・位置を見せない設定(`event_address`)では一緒に隠す。
- Web ページを読む(スクレイピング)方法は採らない(サイトの規約・robots の確認が場所ごとに要るため)。

### ④ 時間の入れ方

- 「開始時刻 〜 終了」を 1 行に並べる。終了は既定で「この場所での時間(何時間何分)」で入れ、印のボタンで「終了時刻(何時まで)」へ切り替える。
- 「終わる日」の選択は外し、終了時刻の時はカレンダーの印で終わる日付も入れられる(既定は日付なし。日付なしで開始より前の時刻は翌日)。
  終わる日は開始の日から 2 日後まで(backend の `end_day_offset` 0〜2 と同じ)。保存する値(`local_end_time`・`end_day_offset`)は変えていない。

### ⑥ メモに 1 文字入れるとカーソルが外れる

- 原因は共通の `Modal`。フォーカスの effect が `onClose` に依存しており、呼び手が描くたびに新しい関数を渡すと 1 文字ごとに effect が走り直して、
  フォーカスを「開く前のボタン → モーダルの枠」へ移していた。`onClose` を ref で持ち、effect は開閉だけに依存させた(全てのモーダルに効く)。
- 重ねて開いたモーダル(スポットの編集の上の写真の選択)は、Esc で一番上だけを閉じる。

### ⑩ コメントとメモの違い(利用者の質問への回答)

- **メモ**(スポットの編集の「メモ」): 予定そのものの説明(見どころ・予約の要否・持ち物)。予定の項目として保存し、しおり・共有にも載る。
- **コメント**(予定の吹き出しの印): 旅行のメンバーとの**相談のスレッド**(相談・投票の画面)。返信・解決済みにできる。予定の内容は変えない。
- 画面の印の名前を「この予定についてメンバーと相談する(コメント)」に変え、違いが分かるようにした。

### その他

- ③⑦ 写真: 予定の写真の画面とスポットの編集の画面で、この端末の写真をドラッグ&ドロップ・ファイルの選択で入れられる。
  旅行の記録(写真)として「自分だけ」・旅行記に入れない設定で取り込む(撮影情報の EXIF はサーバーが外す)。写真があれば編集の画面の上に出す。
- ⑧ 予約・費用: スポットの編集の画面に、この予定に結び付いた予約(`reservations.event_id`)と費用(予定・その予約に結び付いた物)を読むだけで要約する。予約番号は出さない。
- ② 区間の行の「○○から」は外した(2 つの予定の間の行なので)。「変える」「詳細」は色の付いた丸の印のボタンにし、予定の操作(灰色の線の印)と見分けられるようにした。
- ⑪⑫⑬ 「この日を削除」は日のカードの上に控えめな赤い文字の「この日程を削除」として移した(どの日かを読み上げる)。「＋ 日を追加」は「＋ 日程を追加」、
  一覧の下の「＋ 日程に追加する」は「＋ この日にスポットを追加」(Wanderlog の “Add a place”、NAVITIME 旅行プランナーの「スポットを追加」と同じ考え)。
- 同じ旅行を読み直した時(予定の追加・元に戻すの後)に 1 日目へ戻っていたのを、見ている日を保つようにした。予定の追加で終了時刻を送っていなかったのも直した。
