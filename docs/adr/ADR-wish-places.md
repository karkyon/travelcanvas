# ADR: 行きたい場所と場所の入れ方(Gate WishPlaces / SC-47・SC-08)

- 状態: 採用(2026-11-05)

## 決定

1. `/spots` を SC-47「場所を探して保存する」に合わせて作り直す。題名をナビと同じ「行きたい場所」にし、一覧・追加・編集・削除・旅行への追加を 1 画面にする。一覧は本人の場所だけ(`mine=true`)。
2. 手入力・名前の検索・写真・声・SNS・URL を `PlaceFinder` にまとめ、予定の追加でも同じものを使う。選んだ値はフォームへ入り、保存は確かめた後。座標は予定へそのまま渡す(以前の予定の追加は座標を持てなかった)。
3. Web ページは利用者が「読む」を押した時だけ `url_place` で 1 ページ読む(候補箱の FC-019 の例外)。公開アドレスだけ・確かめたアドレスへ直接接続・転送は毎回確かめ直す・HTML 1MB・5 秒。ページの文字は AI へ渡さず保存しない。
4. 画像は EXIF の位置を端末で読み、文字はサーバーの OCR で読む。外部へ送らず保存しない。
5. `/spots` の API をゲストにも開く(ゲストはこの画面が使えなかった)。旅程の操作の列に「しおりを作成」を置く。

## 未確認・制限

- 画像・URL の読み取りに AI は使わない(旅行に属さない呼び出しは FR-059 の口座の扱いの決定が要る)。
- 実際の Web ページ・SNS からの読み取りは未確認(試験は模擬。開発環境から外へ届かない)。多くの SNS は鍵が無いと確かめられず、その時は投稿の文を貼る。
- 名前の検索は既存の検索を使うので、Overpass の障害の影響を受ける。
