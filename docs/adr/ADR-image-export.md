# ADR: しおりの画像出力(FR-046)

- 状態: 採用(Gate P16)
- 前提: Gate P15(Personal Travel Atlas)適用後
- 関連: DOC-02 FR-046、DOC-15 CA-004(しおり画像・PDF出力)・CA-003(共有ポリシー)、DOC-04 SC-36 Export Preview、
  Gate P4(しおり・印刷・PDF、`ADR-booklet.md`)
- トレーサビリティ: `docs/trace/gate-p16-trace.md`

## 1. 背景

FR-046(画像/PDF出力)のうち、PDF・印刷は P4 で実装済み(しおりの版→ブラウザの印刷)。スマートフォン縦長の画像や
LINEで送りやすい画像は無かった。

## 2. 決定

- **backend・DBの変更なし**。画像は端末(ブラウザ)の canvas で描き、PNG として保存する。画像の内容はサーバーへ送らない。
- 画像の元のデータは、しおりのプレビューAPI(P4、booklet-v1 の投影)を **機密項目をすべて含めない設定**(予約番号・住所・電話・
  参加者名=false、章は表紙と日程だけ)で呼んで得る。しおり画面で機密項目を含める設定にしていても、画像には含めない
  (CA-003「URL共有、公開画像、PDF出力ごとに異なるPolicy」)。QR・チケットの中身はしおりの投影にそもそも含まれない。
- 範囲: 旅行全体 / 1日。形式: スマートフォン縦長(1080×1920)/ 正方形(1080×1080、LINE等)。
  入りきらない時はページを分け(1/2…)、各ページに旅行名・日付を描く。長い行は幅に合わせて折り返す。
- 各ページの下に、生成日時・旅程の版(最新/古い)・含めていない情報を必ず描く。投影の後に旅程が更新されていれば
  画像に警告を描き、画面でも作り直しを案内する(CA-004「STALEには警告」)。
- 作る前に、含める情報と含めない情報を画面に示す(CA-004「出力前に含有項目を確認」)。
- 保存は data URL を一時的な Blob の URL にして行う(data URL のままではブラウザがファイル名を無視する)。ファイル名は
  「旅行名_範囲(trip か日付).png」。範囲の部分はASCIIにする(一部のブラウザは非ASCIIのファイル名を捨てるため)。
- 権限はしおりのプレビューと同じ(editor 以上。DOC-04 §9 SC-26)。
- レイアウト(どの文字をどこに描くか)は文字幅の測り方を受け取る純粋関数にし、描画(canvas)と分けて試験する。

## 3. 未実装(本Gateの範囲外)

- NOW/NEXT カードの画像化(当日画面から)
- 地図・写真入りの画像、テーマ(色・書体)ごとのデザイン
- 画像の作成を監査に記録すること(画像は端末の中で作るため、現在はサーバーに記録が残らない)
- サーバー側での画像生成(端末で canvas が使えない環境では作れない旨を表示する)
