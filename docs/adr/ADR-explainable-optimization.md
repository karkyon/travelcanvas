# ADR: 説明可能な最適化(FR-018)を制約・実行可能性検証へ接続する(B-007)

- 状態: 採用(Gate L4)
- 前提: Gate P10(アラート・再計画)適用後
- 関連: DOC-02 FR-018・FC-058(最適化再現)・FC-059(部分最適化)、DOC-04 SC-16、DOC-10 B-007、共通不変条件3・4
- トレーサビリティ: `docs/trace/gate-l4-fr018-trace.md`

## 1. 背景

Gate #33の最適化(`/optimization-proposal`、nn-haversine-v1)は、1日の予定の並び順だけを近傍法で入れ替えていた。
- 時刻を変えないため、並べ替え後に「順番」と「時刻」が食い違った(10:00の予定が11:00の予定の後ろに並ぶ)。
- 制約(L2)と実行可能性検証(L3)を入力にしておらず、制約違反を増やす並べ替えも「改善」と表示した(B-007)。
- 予約付きの予定も動かしうるため、予約時刻と旅程がずれる可能性があった。

## 2. 決定

### 2.1 候補の作り方(explainable-opt-v1、`app/services/optimizer.py`、DB非依存)

- 動かさない予定: 確定(ロック)済み、予約(reservations.event_id / event_reservations)と紐付く予定、終日、位置(緯度経度)なし。
  時刻のある予定と時刻のない予定が混在する日は、時刻のない予定も動かさない(時刻を失わせない)。元の位置・時刻のまま。
- 動かす予定の並び順を入れ替え、時刻は「枠」として扱う: 動かす予定が元々持っていた開始時刻を早い順に、新しい並び順へ割り当て直す。
  終了時刻(end_at)・開始日時(start_at)を持つ予定は、所要時間を保ったまま一緒に動かす(P7の`_apply_time`と同じ規則)。
- 並び順の候補: 現在の順、各地点からの最近傍法、最も短い順への2-opt改善。動かす予定が6件以下なら全ての並び順(最大720通り)。
  13件以上は計算しない(注意を返す)。同じ入力からは同じ候補・同じ識別子(並び順と時刻のハッシュ)になる(FC-058)。

### 2.2 評価(制約・検証との接続)

- 各候補について、移動距離・移動時間(内部推定、直線距離×迂回係数、`route_estimator`)と、
  時刻・並び順を変えた仮のスナップショットに対する実行可能性検証(feasibility-v1、制約L2を含む)を計算する(DBは変えない)。
- 「移動が最短の案」: 距離が最も短い候補(今より0.01km以上短い場合だけ)。
- 「制約・検証を優先した案」: (エラー件数、守れていない制約の件数、注意の件数、距離)が最も小さい候補(今より良い場合だけ)。
  同じ候補なら1つにまとめる。
- 今の順との比較(距離・時間・エラー・注意・守れていない制約・検証できない項目)、新たに出る問題・解消する問題、
  順番・時刻の変化、理由の文(「守れていない制約が1件減ります」など)を返す。秘匿制約の値は判定側(feasibility-v1)で文面に含めない。

### 2.3 適用

- `POST .../optimization-candidates/apply`: If-Match(本案のrevision)と、候補を計算した時の入力の版
  (`input_fingerprint` = 旅程・制約・予約・紐付け・区間の版、L3と同じ)を送る。
- サーバーで同じ入力から候補を計算し直し、指定された候補が無ければ409 `candidate_not_found`。入力の版が変われば409 `optimization_stale`。
- 並び順と時刻をまとめて1つの変更セット(source=optimization)で記録し、本案の「元に戻す」で全て戻る。監査は件数・方式だけ。
- 権限: 計算はviewer以上(`can_apply`で適用可否を返す)、適用はeditor以上。ゲストも自分のプランで使える。

### 2.4 互換

- Gate #33の `/optimization-proposal`・`/apply` は残す(画面は新しい候補APIへ切り替えた)。

## 3. 今回の範囲外

- 公平性(メンバーごとの希望の満足度)・疲労の指標、条件(重み)を変えた再計算、部分採用(DOC-04 SC-16)。
- 日をまたぐ並べ替え、予定の追加・削除を含む最適化、外部の経路サービスによる実移動時間(provider接続のGate)。
- 非同期のジョブ化(DOC-06 `/optimizations/{job_id}`)。現状は1日・最大720通りを同期で計算する。
