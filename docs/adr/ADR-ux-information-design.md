# ADR: 文脈型ダッシュボードと見出しの情報の置き方(UX-3・UX-4)

- 状態: 採用(Gate G9 後半)
- 関連: 再監査報告書 §8、DOC-04 §1(UI設計原則)・SC-04(旅行一覧)、`docs/adr/ADR-design-tokens.md`、`docs/ux/UX-0_baseline.md`
- トレーサビリティ: `docs/trace/gate-g9b-trace.md`

## 1. 背景

UX-0 の記録(G9 前半)で、ダッシュボードの最上段が「登録スポット・お気に入り・訪問済み」の数で、続きの旅行・次に
すべきことが分からないこと、全体の見出しの項目名が折り返し「AI検索」が2か所にあること、旅行の画面で旅行名より先に
23個の操作が並ぶことが分かった。

## 2. 決定

### 2.1 ダッシュボードは「次に何をすべきか」を最上段に(UX-4)

- backend に読み取りだけの集約 `GET /api/v1/dashboard` を置く。見られる旅行(所有・参加。削除済みを除く。最大50件)を
  **旅行中・旅行前・旅行後・日付未定**に分け、焦点の旅行を1つ選ぶ:
  旅行中(開始が早い順)→ 旅行前(開始が近い順)→ 30日以内に終わった旅行(終わりが新しい順)→ 日付未定(作成が新しい順)。
- 段階は旅行の最初の日程のタイムゾーン(無ければ Asia/Tokyo)の「今日」と日程の日付で決める(端末の時計に依らない)。
- 焦点の旅行の中身は**既存の画面と同じ関数**で作る(当日 = `get_today`、準備 = `get_readiness`、遅延と休業 =
  `list_alerts`)。そのため参加者に見せない設定(member_policy)の項目は、それぞれの画面と同じく隠れる。1つの計算が
  失敗しても、その欄だけ null にしてダッシュボード全体は返す。
- 画面(`DashboardPage`):
  - 旅行が無い → 「最初の旅行を始めましょう」と旅行を作る入口。
  - 旅行中 → 表紙・今と次(現地の時刻・残り時間)・準備・遅延と休業。
  - 旅行前 → 表紙・準備(上位3件)・遅延と休業。
  - 旅行後 → 精算・記録・訪問の確認・振り返りへの案内。
  - 操作は段階ごとに**最大4つ**。権限の無い操作は出さない(招待は所有者だけ、日程を決めるのは編集できる人だけ)。
  - その下に段階ごとの旅行の一覧(表紙のカード。最初は9件)と、スポット・地図への入口。
- 状態: 読み込み中(role=status)・失敗(role=alert・問い合わせ番号・再試行)・オフライン(つながったら読み直す)。
- 状態は色だけで伝えない(「旅行中」「重要」「閲覧のみ」などの文字を必ず添える)。
- 最初に読む JS を増やさない(API・decoder・画面は後から読む塊。`g9.ts`・`decodersG9.ts`)。

### 2.2 全体の見出し・旅行の中の移動(UX-3)

- 全体の見出しは高さ 64px で一定。項目名は折り返さない(md〜lg はアイコンと読み上げの名前だけ、lg 以上で名前を見せる)。
  利用者名は xl 以上で見せ、長い名前は省略する。「AI検索」はメニューの1か所だけ(重複していたボタンと点滅する印を外した)。
- 旅行の画面にいる時は見出しに「旅行: <題名>」を出す。見出し(最初に読む JS)が旅行の入れ物(`planStore`)を読み込むと
  約30kB 増えるため、今開いている旅行の id・題名だけの小さな入れ物(`currentTripStore`)へ写す。
- 通知のリンクは未読の数を名前に含める。利用者のメニューは `aria-expanded` で開閉を伝える。スマホのメニューは一覧(ul)。
- 旅行の画面は表紙の見出し(状態・題名・行き先・期間・オフラインの印)を最初に置き、その後に23個の入口を目的ごとの
  5つのまとまり(当日・計画・予約と準備と費用・一緒に・記録と振り返り)で並べる。入口の名前・行き先は変えない。

## 3. 採らなかった案

| 案 | 理由 |
|---|---|
| 画面から旅行ごとに today・readiness・alerts を呼ぶ | 旅行の数だけ通信が増え、見せない設定の扱いを画面側で重ねて書くことになる |
| 焦点を利用者に選ばせる | 5秒で次にすることが分かる、という目的に合わない。一覧から旅行を開けば足りる |
| GlassyDashboard2(以前の試作)を使う | デザインの決まり(tokens・Surface)の外の色・面を使っており、コントラストを確かめられない |
| スマホの下に固定の移動の帯を置く | 当日の画面の固定の操作と重なる。見出しのメニューと旅行の画面のまとまりで足りるため、必要なら UX-5 で当日の画面と一緒に決める |

## 4. 未実装・制約

- 表紙の写真の読み込み(ADR-design-tokens §2.1)。
- 暗い見た目はダッシュボードだけ(全体は UX-8)。
- 旅行が50件を超える利用者は、新しく作った50件だけを分ける(それ以外は旅程の一覧から開く)。
- ダッシュボードの数値(旅行中・旅行前などの件数)を KPI として記録することはしない(FR-001 の KPI は別)。
