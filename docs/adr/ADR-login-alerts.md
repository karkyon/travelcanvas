# ADR: 新しい端末からのログインの通知と、ログイン中の端末の一覧(Gate S9)

- 状態: 採用
- 対象: セキュリティ整理 SEC-09 の一部(乗っ取りの検知)、FR-003 の不足「session一覧UI」
- 関連: Gate #28(セッション・個別失効の API)、Gate S2(refresh の行ロック)、Gate S6/S7/S8

## 背景

AI を使ったパスワードリスト攻撃は、当たったアカウントに静かに入る。回数制限・自動遮断・計算の確認は
「当たるまでの試行」を減らすが、当たった後の侵入には本人しか気付けない。ところが本人には、どの端末で
ログインしているかを見る画面も、新しい端末からのログインを知る手段も無かった(API はあったが画面が無い)。

## 決定

1. ログインに成功した時、端末(User-Agent から作る「ブラウザ / OS」の組)が過去90日のどのセッションとも違えば、
   本人に通知(notifications、`new_device_login`)を作り、監査に `login_new_device` を残す。初めてのログインと、
   失敗したログインでは作らない。通知には丸めた接続元(IPv4 は /24、IPv6 は /48)を書き、完全な IP・メール・
   パスワードは書かない。通知の失敗でログインは止めない。
2. セッションに端末の名前(`device_info.device`)を保存する。以前の版のセッションは User-Agent から作る。
3. `GET /auth/sessions` に `device_label`・`network_label`・`last_active_at` を足す(既存の項目はそのまま)。
4. 設定 → セキュリティに「ログイン中の端末」: 端末・丸めた接続元・ログインの日時・最終利用・この端末の印、
   ほかの端末を1台ずつ、またはまとめてログアウト(既存の `DELETE /auth/sessions/{id}`)。
5. 設定画面のタブは「描画のたびに別の部品として作り直す」形だったため、入力欄が1文字ごとにフォーカスを失っていた
   (パスワードを続けて打てない)。タブを描く関数に変え、パスワード欄に label を結び付けた。

## 採らなかったもの

- メールでの通知: SMTP の設定が無い。通知の仕組みに乗せているので、メールの送信を足す時はそこから送れる。
- 細かい端末の識別(版・画面の大きさ等): 個人を追跡できる値を増やさない。同じブラウザと OS の組を使う攻撃者は
  「新しい端末」にならない(一覧で確かめる)。
- 接続元の地域の表示: 外部の位置情報サービスが要る。

## 影響

- ブラウザを替えた・OS を更新して名前が変わった時にも通知が出る(本人には害が無い)。
