# ADR: デザインの決まり(design tokens)と面(surface)の4種類(UX-1)

- 状態: 採用(Gate G9)。UX-5・UX-6・UX-8 を Gate G10-UX で追加(§2.3〜§2.5)
- 関連: 再監査報告書 §8「Cinematic Travel Workspace」、DOC-08 §2(Tailwind CSS + tokens)、DOC-10 UX品質Gate
- トレーサビリティ: `docs/trace/gate-g8-trace.md` の G9 の節、`docs/trace/gate-g9b-trace.md`(UX-2〜UX-4)、`docs/ux/UX-0_baseline.md`
- 関連する判断: `docs/adr/ADR-ux-information-design.md`(ダッシュボード・見出しの情報の置き方)

## 1. 背景

画面ごとに Tailwind の色(gray-400 など)を直に書いており、コントラストの不足(axe の color-contrast)が画面を足すたびに
見つかっていた。見た目を一段上げる改修(UX-2 以降: 旅行の表紙・すりガラスの面・地図を背景にした当日の画面)の前に、
値を1か所に決め、読みやすさを機械で確かめられるようにする。

## 2. 決定

- 正本は `frontend/src/styles/tokens.ts`。同じ値を `tokens.css` の CSS 変数(`--tc-*`)に置き、試験
  (`tokens.test.ts`)で一致を確かめる。Tailwind からは `@theme inline` で `tc-*` の名前で使える。
- 色は Ink(文字)・Cloud(地)・Sand(温かい地)・Mist(冷たい地)と、旅行ごとの強調色1色。状態(成功・注意・危険・情報)は
  装飾の色と分け、必ず文字やアイコンと一緒に使う。決めた文字と地の組み合わせ(`TEXT_PAIRS`)は全て WCAG 2.1 AA
  (本文 4.5:1、フォーカスの枠 3:1)を満たすことを試験で確かめる。
- 旅行の表紙から取った強調色は `safeAccent()` で白い地の上で 4.5:1 以上になるまで暗くする(形が違えば既定の色)。
- 面は **glass・solid・quiet・critical の4つだけ**(`components/design/Surface.tsx`)。glass(すりガラス)は見出しの帯・
  旅行の切り替え・NOW/NEXT・浮かぶ操作だけに使い、フォーム・表・チケット・警告・長文は solid。glass の上に glass を
  重ねない(CSS で中の glass を solid にする)。
- すりガラスを使えない環境(backdrop-filter 未対応・透明を減らす設定・強制の色)では不透明の面に落とす。動きは
  150〜220ms で状態の変化を伝えるだけ。動きを減らす設定では止める。
- 暗い見た目は `data-theme="dark"` の中だけ(UX-8 で全体へ広げるまで、今の画面には当てない)。
- 一覧は `/design-system`(Storybook の代わり。ログイン不要・利用者のデータを含まない)。E2E で明るい・暗いの両方に
  axe をかける。

### 2.1 旅行の表紙(UX-2、G9 後半)

- 写真が無い旅行の表紙は**生成のグラデーション**(`COVER_PALETTES` の8色の組。春・夏・秋・冬に2つずつ)。
  `coverFor({destination, title, startDate})` は行き先(無ければ題名)の FNV-1a の値で選び、開始の日があればその季節の
  2つから選ぶ。同じ旅行は常に同じ色(試験 `cover.test.ts`)。
- 表紙の上の文字は白。全ての色の両端で白い文字が 4.5:1 以上(`TEXT_PAIRS` と `cover.test.ts` で確かめる)。
  さらに下側に暗い覆い(`.tc-cover::after`)を重ね、模様(`::before`)は飾りだけで文字の後ろを暗くしない。
  強制の色(forced-colors)では模様・覆いを消し、地の色と枠だけにする。
- 部品は `components/trip/TripCover.tsx`(大きさ hero・header・card)。ダッシュボードの最上段・旅行の一覧のカード・
  旅行の画面の見出し(`PlanHeader`)で同じ部品を使う。
- **写真の読み込み(アップロード)は本 Gate で作らない**。作る時は別の Gate で、記録の写真(FR-037)と同じく
  形式(MIME と中身の一致)・大きさ・EXIF の位置情報の除去・暗号化した保存・参加者の見せる範囲を満たす。
  それまで migration・保存場所は増やさない。
- **[Gate G11] 表紙の写真**(`docs/ux/G11_UIUX全範囲_実装仕様.md` §1〜§3.1): 写真は記録の写真(FR-037)をそのまま使い、
  保存場所を増やさない(`travel_plans.cover_memory_id` が記録を指す。記録が消えたら NULL)。写真の上の重ねは
  `COVER_PHOTO_SCRIM`(上 0.62・下 0.8 の ink900)で、真っ白の写真の上でも白い文字が 4.5:1 以上(`cover.test.ts`)。
  写真の時は等高線の模様を消す。見せる位置(横・縦 %)と拡大(100〜300 %)は `object-position` と `scale` で、
  hero・header・card の全ての大きさで同じ中心になる。強制の色では写真を出さない。外部の写真は出典を右下に出す。

### 2.2 暗い見た目の範囲(G9 後半)

- ダッシュボードだけ、閲覧する人が「端末に合わせる・明るい・暗い」を選べる(`useThemePreference`。この端末の
  localStorage `tc.theme`。読めない環境では「端末に合わせる」)。他の画面は UX-8 まで明るいまま。
- 暗い見た目の状態の色(成功・注意・危険・情報の淡い地)と強調の文字の色を `darkColor` に足し、`TEXT_PAIRS` で AA を確かめる。

### 2.3 暗い見た目を全ての画面へ(UX-8、G10-UX)

- 選択(明るい・暗い・端末に合わせる)はアプリの全体で1つ(`hooks/useThemePreference.ts` の zustand の小さな入れ物。
  この端末の localStorage `tc.theme`)。`components/design/ThemeRoot.tsx` が `<html data-theme>`・`color-scheme`・
  `<meta name="theme-color">` に当てる。選べる場所: 見出しのユーザーのメニュー(表示: 明るい・暗い・端末)・設定の
  「テーマ」(以前はサーバーに保存するだけで画面に効いていなかった)・ダッシュボードの「表示」。
- 今の画面は Tailwind の色を直に使うため、**橋渡し**(`styles/darkBridge.ts` → 生成の `styles/theme-dark.css`)で、
  `[data-theme='dark']` の中だけ、使われている色のクラスを暗い地で読める値に置き換える: 地味な色(gray 等)は明暗を
  反転、色付きの淡い地(bg-red-50 等)は暗い地にその色を少し混ぜる、濃い文字(text-red-800 等)は淡い色、色の濃い地
  (bg-blue-600 + 白い文字)と白い文字はそのまま、白い地は面の色。
- 試験(`darkBridge.test.ts`)で、(1) 生成した CSS が最新、(2) src の**全ての色のクラスが置き換えか「そのままで良い」**
  のどちらかに入る(漏れが無い)、(3) 置き換えた文字の色が暗い地・面・同じ色の淡い地のどれでも 4.5:1 以上、を確かめる。
  E2E(`gate-g10-ux.spec.ts`)で主な9画面を暗い見た目の 1440px・360px で開き、axe(コントラストを含む)違反 0。
- 暗い見た目は**画面だけ**(`@media screen`)。印刷(しおり)は白い紙のまま。しおりの部品は置き換えの対象から外した。

### 2.4 共通の部品をデザインの決まりへ(UX-6、G10-UX)

- `Button`(主な操作は強調色の1色・文字は `on-accent`、危険は `danger-solid`・フォーカスの枠は `focus`)・`Card`(solid の面)・
  `Input`・`Modal`(Tailwind v4 で無くなった `bg-opacity-50` のため覆いが真っ黒だったのを `bg-black/50` に)・`Toast`・
  `LoadingSpinner`・`Layout`・見出しのメニューを tokens の色へ置き換えた。読み込み中の通知(react-hot-toast)の青は白い文字と
  3.7:1 だったため #1d4ed8(6.7:1)へ。
- 全ての画面の文字の灰色(`text-gray-500〜900` → `text-ink-*`)と白い面(`bg-white` → `bg-surface`)を置き換えた
  (意味が同じで、明るい見た目ではほぼ同じ色。暗い見た目では決まりの値)。画面に直に書いた色のクラスは 3,338 → 1,632 件。
  `darkBridge.test.ts` の基準(`MAX_DIRECT_COLOR_CLASSES`)より増やさない。残りは状態の色・淡い地など(画面ごとに置き換える)。

### 2.5 当日の画面(UX-5、G10-UX)

- DOC-04 §1(重要情報1操作)・§14(片手・親指の届く所)・§16(アクセシブル当日モード)に合わせて作り直した
  (`pages/TodayPage.tsx`・`pages/today/TodayParts.tsx`・`todayModel.ts` の `computeTodayFlow`)。
- 上: 日付・現地時間の注記・つながりの状態(「最新」「保存済み」を文字とアイコンで)・更新(44px)。
  今(NOW): 残りの分と進みの棒(`role=progressbar`)・地図・チケット。次(NEXT): 出発まで(大きく)・遅延・地図・チケット。
  その後に「この後の予定」(NOW・NEXT を重ねない)と済んだ予定の数。「簡易表示」は今と次だけ(端末に覚える)。
- スマホでは「遅延・休業などの対応」「プランへ」を画面の下に固定する(safe-area を足す)。押せる高さ 48px。
- 状態は色だけで伝えない(NOW・NEXT・進行中・次の予定・遅延・運休・定刻は文字)。面は solid と quiet だけ(当日の画面の
  地図の背景は別の Gate。glass は背景が無いと効果が無い)。

## 3. 採らなかった案

| 案 | 理由 |
|---|---|
| Storybook を入れる | 依存と CI の時間が増える。部品の数が少ないうちは1画面の一覧と E2E の axe で足りる |
| 今の画面の色を一度に置き換える | 見た目の変化が大きく、壊れた所を見分けられない。UX-0 の記録と比べながら UX-6 で順に置き換える |
| 暗い見た目を今すぐ全体に当てる | 今の画面は Tailwind の色を直に使っており、暗い地で読めない所が残る(G9 の時点。G10-UX で §2.3 の橋渡しにより全体へ) |
| (G10-UX)Tailwind の色の変数(--color-gray-700 等)を暗い見た目で入れ替える | 同じ変数が地と文字の両方に使われる(bg-blue-700 の地と text-blue-700 の文字)。入れ替えると色の濃い地に白い文字のボタンが読めなくなる。クラスごとの置き換えなら地・文字・枠を別に決められる |
| (G10-UX)画面を1つずつ書き直してから暗い見た目を当てる | 60 を超える画面を一度に書き直すと壊れた所を見分けられない。橋渡しで全体を読めるようにし、直書きの色は基準を下げながら減らす |
| 表紙の写真をこの Gate で読み込めるようにする | 位置情報(EXIF)の除去・形式の確認・保存の暗号化・見せる範囲の設計が要り、見た目の改修と混ぜると確かめにくい。生成の表紙で全ての旅行に表紙が付く |
| 表紙の色を無作為に選ぶ | 開くたびに色が変わり、旅行を色で覚えられない |
