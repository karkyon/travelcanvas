# ADR: Memory Replan(FR-057)の最小実装

- 状態: 採用(Gate P17)
- 前提: Gate P16(画像出力)適用後
- 関連: DOC-02 FR-057、DOC-15 CA-015(Memory Replan)、Gate P14(旅の振り返り、event_actuals)
- トレーサビリティ: `docs/trace/gate-p17-trace.md`

## 1. 背景

P14 で予定と実績を分けて記録できるようになったが、その実績を次の旅行の計画に活かす仕組みが無かった。

## 2. 決定

- **migrationなし**。提案は毎回、閲覧者が参加している「ほかの旅行」の予定と実績(P14)から集計する(memory-replan-v1)。
  AIは使わない(機微情報を外部へ送らない。CA-015)。
- 傾向(根拠の件数・旅行・例を必ず付け、件数が足りなければ出さない):
  - 滞在が予定より長い/短い: 同じ種類の予定で、実際の滞在(到着→出発)と予定の滞在(同じ日の次の予定の開始まで)の差の平均が15分以上(2件以上)
  - 到着の遅れ: 予定の開始より平均10分以上遅れて着く(3件以上)
  - 行かないことが多い: 同じ種類の予定の半分以上に「行かなかった」(2件以上)
  分は5分単位に丸める。
- 提案(適用できるのは「滞在が長い」だけ): この旅行で、その種類の予定の後に続く同じ日の予定を平均の分だけ後ろへずらす。
  確定(ロック)・予約付きの予定は動かさず、それより後ろも動かさない(順番が入れ替わらないように)。24時を超えるずらしは作らない。
  同じ日に同じ種類の予定が複数あっても、ずらすのは1回分だけ(控えめにする)。ほかの傾向は助言だけで旅程を変えない。
- 適用: If-Match(本案のrevision)と input_fingerprint(提案を作った時の旅程・予約の紐付け・傾向の版)を確認し、
  違えば409 replan_stale。1つの変更セット(source=memory_replan)で記録し、本案の「元に戻す」で取り消せる。
- 権限: 提案を見るのは viewer 以上、適用は editor 以上。材料は閲覧者が参加している旅行だけ(参加していない旅行の実績は使わない)。
- 監査には種類・件数・分だけを残し、予定名を残さない。

## 3. 未実装(本Gateの範囲外)

- 子連れ・同行者の属性ごとの傾向、移動手段の傾向(「徒歩20分超で交通手段を変えやすい」)
- 提案ごとの個別の採否(変わる予定を1件ずつ選ぶ)
- 予定の終了時刻(滞在時間)そのものを持つこと(現在は次の予定の開始までを予定の滞在として扱う)
