# ADR: 写真・メモ・旅行記(FR-037)の最小実装

- 状態: 採用(Gate P12)
- 前提: Gate P11(オフライン編集・同期)適用後
- 関連: DOC-02 FR-037、DOC-04 SC-28(写真・旅行記)・§9(画面別権限: SC-28 Travelogue)、DOC-14 §4.5 MEMORY MAP・§7.4、
  DOC-15 CA-012(Plan-to-Memory)、DOC-11 §23(Privacy by Default)、FR-039(書き出し・削除)
- トレーサビリティ: `docs/trace/gate-p12-trace.md`

## 1. 背景

FR-037(イベント・場所・日時へ写真、動画参照、音声メモ、文章を紐付け、計画と実績から旅行記の下書きを生成し公開範囲を確認する)は
全く無かった。あわせて、データの書き出し(FR-039)に P7(旅程ブランチ)・P10(アラート・再計画)・P11(同期の受領記録)の表が
含まれていない漏れが見つかったため、本Gateで修正し、漏れを検査する試験を追加する。

## 2. 決定

### 2.1 データ(migration `b9d5f3a7c1e4`、1テーブル新設のみ)

- `memories`: 種類(note/photo/audio/video)、本文、予定・日(event_id/day_id)、日時(occurred_at、タイムゾーン必須)、
  場所の名前・緯度経度、動画のURL、写真・音声のファイル(storage_key・MIME・サイズ・SHA-256)、
  公開範囲(private=書いた本人だけ/members=旅行のメンバー)、旅行記に使うか(include_in_journal)、revision。
- 種類と項目の対応(写真・音声はファイル必須、動画はURL必須、メモは本文必須、緯度経度は両方か無し)をDBのCHECKで保証する。
- 予定・日には外部キーを張らない(B-013の個別削除を妨げないため)。予定が消えた記録は「そのほかの記録」に表示する。
  plan_id は ON DELETE CASCADE(B-012の外部キー方針)。

### 2.2 ファイル

- 写真(jpg/png/gif/webp)・音声(mp3/m4a/wav/ogg/webm)を拡張子と先頭バイトで検証し、文書と同じ保存先へ暗号化して保存する
  (`storage_backend.save_encrypted_file`、上限は文書と同じ `DOCUMENT_MAX_UPLOAD_SIZE_BYTES`)。
- 動画はファイルを保存せず、https のURLの参照だけを持つ(認証情報入りのURLは拒否。画面のリンクは `rel="noopener noreferrer"`)。
- ファイルは `GET /memories/{id}/media` で、見える人にだけ返す(`Cache-Control: no-store`)。画面はBlobを一時URLにして表示し、
  ファイルのURLを共有・保存させない。
- ウイルス検査・EXIF(撮影位置)の除去は行わない(外部AVエンジン・画像処理ライブラリ未導入。§4)。
  保存したファイルは本人とメンバーが画面で見るだけで、旅行記の下書き(テキスト)には写真の中身を含めない。

### 2.3 権限・公開範囲(DOC-04 §9 SC-28)

| 操作 | 所有者 | 編集者 | 閲覧者 | 部外者 |
|---|---|---|---|---|
| 一覧(自分の記録+メンバーに公開された記録) | ○ | ○ | ○ | 403 |
| 記録の作成(メモ・動画・写真・音声) | ○ | ○ | 403 | 403 |
| 変更(If-Match: 記録のrevision) | 本人の記録だけ | 本人の記録だけ | — | — |
| 削除(ファイルも消す) | 本人の記録+メンバーに公開された記録 | 本人の記録だけ | — | — |
| 旅行記の下書き | ○ | ○ | ○ | 403 |

- 他人の「自分だけ」の記録は、一覧・ファイル・変更・削除のどれでも404にし、件数も含めて存在を知らせない。
- 監査には種類・公開範囲・サイズ・変えた項目名だけを記録する(本文・場所・ファイル名は残さない)。

### 2.4 旅行記の下書き(journal-draft-v1、`app/services/memories.py`)

- 計画(日・予定)と実績(予定へ紐付けた記録)から、日ごと・予定ごとの下書き(構造+Markdown)を作る。保存しない・旅程は変えない。
- 計画した予定は記録が無くても「予定していた場所。記録はありません」として残し、予定と実績を混同しない(DOC-15 CA-012)。
- 選択肢: 位置を含める(既定: 含めない)/写真・音声・動画を含める(既定: 含める。中身ではなく「写真(アプリで表示)」と書く)/
  他のメンバーが公開した記録を含める(既定: 含めない)。旅行記に使わない記録は含めない。
- 公開前の検査(SC-28「顔、位置、同行者名、予約情報を公開前に検査」):
  同行者の名前(閲覧者本人を除くメンバーの表示名)、予約番号のような文字列(英大文字と数字を両方含む6〜12文字)、
  電話番号のような文字列、写真(顔の自動判定はしないため確認を促す)、位置を含める場合の注意、他のメンバーの記録を含める場合の注意。
  検査結果には見つかった文字列そのものを載せない(検査結果から機密値を広げないため)。

### 2.5 削除・書き出し(FR-039)

- 記録の削除: 行とファイルを消す(ファイルの削除に失敗しても行は消し、ログにはplan_idだけを残す)。
- 旅行の完全削除(B-012): 文書に続いて記録のファイルを消し、消せなければ完全削除を保留して再試行する(行は旅行と一緒に連鎖して消える)。
- アカウント削除(P9): 参加している旅行に本人が残した記録とファイル、本人の同期の受領記録(P11)を消す。
  削除内容の説明(preview)に記録の件数を出す(`deleted_in_member_plans.memories`)。
- 旅行の書き出し(P6): `memories`(本人の記録とメンバーに公開された記録。保存キーは含めない)と、漏れていた
  `itinerary_branches`・`plan_alerts`・`replans`・`sync_operations`(本人が送った分だけ)を追加。
  アカウントの書き出しの参加分(contributions)にも本人の記録を追加。
- 旅行(plan_id)を持つ表が書き出しから漏れていないことを、DBのメタデータから検査する試験を追加した(再発防止)。

### 2.6 画面(`/planner/:planId/memories`、プラン画面の「📷 旅の記録」)

- 記録の追加(種類・ファイル・URL・メモ・予定・日時・場所・公開範囲・旅行記に使うか)。ファイルの形式・大きさ、動画のURLは
  送る前にも確かめる(サーバーでも同じ検証をする)。
- 日ごとの一覧(写真は代替テキスト付き、音声は再生欄、動画は外部リンク)。本人はメモの編集・公開範囲・旅行記に使うかを変えられる。
- 旅行記の下書き(選択肢・件数・公開前の確認・Markdown・コピー・.md保存)。

## 3. 代替案

- 写真のEXIF位置を読み取って記録の位置にする: 位置情報の同意(P9)と位置軌跡(FR-038)の設計に合わせて行うため、本Gateでは行わない。
- 旅行記を保存して公開URLで共有する: 公開ページの方針(検索エンジン除外・失効・投影、FR-035/045)と合わせて設計する必要があり、
  本Gateは下書き(コピー・保存)までとした。

## 4. 未実装(本Gateの範囲外)

- 旅行記の保存・公開(公開URL、版、失効)と、公開範囲の項目別の設定(SC-28 公開範囲を項目別に選択)
- 写真のEXIF(撮影位置・撮影時刻)の読み取りと除去、顔の自動判定、サムネイル生成、ウイルス検査
- 音声メモの文字起こし、動画ファイルの保存
- 写真・記録の地図表示(MEMORY MAP、DOC-14 §4.5)、位置軌跡(FR-038)との近接による自動紐付け
- 記録の変更・削除のUndo(変更セットへの記録)
- オフラインでの記録の作成(P11の同期は予定だけが対象)

## 5. 追補(Gate G11): 旅行の表紙・予定の写真

- 旅行の表紙(`travel_plans.cover_memory_id`)・予定の写真(`travel_events.image_memory_id`)は、この記録(kind=photo)を指すだけで、
  ファイルを複製しない。記録が消える(ゴミ箱へ移す・退会)と外部キー(ON DELETE SET NULL)で外れる。ゴミ箱から戻しても表紙には戻さない。
- 表紙にしても記録の公開範囲は変えない。見えない人には表紙の情報も写真も返さない(`app/services/plan_cover.py`)。
- 配信は `GET /plans/{id}/cover/media` で、`GET /memories/{id}/media` と同じ処理(`media_response`: 撮影情報の除去・no-store・
  nosniff・CSP sandbox)。旅行の複製は表紙をコピーしない。
- `memories.source`(JSONB): 外部から取り込んだ写真の出典(G11 段階3。手で上げた写真は NULL)。
