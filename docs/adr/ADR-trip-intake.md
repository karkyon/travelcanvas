# ADR: 行き先が未定の旅行相談(Gate G11-Intake)

- 状態: 採用(2026-10-29。利用者の決定「以前対象外とした機能を全て G11 に入れる」と、2026-10-29 の統合ハンドオフ §3・§4。
  仕様 `docs/ux/G11_UIUX全範囲_実装仕様.md` §2.5・§3.5)
- 関係: `ADR-quick-draft.md`(行き先が決まっている時の入口)、`ADR-media-providers.md`(近くの検索・出典)、DOC-11(プライバシー)

## 1. 決めたこと

| 項目 | 決定 |
|---|---|
| DB | **migration なし**。下書きの条件・方面・並びは `travel_plans.preferences["trip_intent"]`(JSON)、場所は既存の `plan_candidates`、旅程にする時に既存の `travel_days`・`travel_events`(ChangeSet 1つ)。仕様に無い DB の変更をしない(作業指示 r2「判断が要る時」) |
| 文章の読み取り | 決まった規則(正規表現)だけ(`app/services/trip_intent.py`)。**AI の provider は未接続**で、画面・API は「文章から読み取り · 未確認」「AI の読み取りは未接続」と言う(AI の判断と偽らない)。読み取った行は利用者が確かめるまで条件に使わない |
| 曖昧さ | 片道の時間は「希望/絶対条件」、宿泊費は「全員の合計(1部屋・1泊)/1人あたり」を問いにする。文章の書き方からの提案(くらい → 希望、4人で → 合計)は示すだけで決めない。日付が無ければ宿・営業時間は照会しない |
| 方面 | 利用者が書いた・足した方面だけ(「AやB、Cなどが候補」「候補は A・B」「滋賀(湖東/湖西)」を分ける)。**自動の方面の提案は未接続**(作り話の候補を出さない) |
| 位置 | Nominatim(地名の照会)。利用の条件に合わせ **1秒に1回**・同じ地名は1日覚える。状態 ok/not_found/unavailable/disabled。設定 `TRIP_INTENT_GEOCODER`(空で止める) |
| 運転・宿・混み具合・営業時間 | 提供元が未接続か日付待ち。値を作らない。片道の条件は **直線距離 ÷ 時速100km**(運転時間の下限)で明らかに超える時だけ印を付け、他は「未確認」 |
| 点数 | 方面の相性の点数は出さない(根拠が無い。モック v2 の決定) |
| 個人的な理由 | 記念などの語は返さない・保存しない(「個人的な理由」とだけ確認の画面に示す)。下書きに残すのは決まった項目だけ(文章・理由は API が受け取らない) |
| 下書き | 選んだ方面の候補だけから旅行(`status=draft`)を作る。日程はまだ作らない。並びは時間帯(午前・昼食・午後・夕方・宿)。日付と IANA の時刻帯を決めた時に旅程(日・予定、時刻は未定)にし、旅程の画面の「元に戻す」1回で戻る(戻ると下書きに戻る) |
| 試験 | 外部へつながない。backend は地名の照会を差し替え・`httpx.MockTransport`、E2E は外部に頼る応答(方面の位置・近くの検索・地図の画像)だけ `page.route` で差し替える |

## 2. 代替案

| 案 | 採らなかった理由 |
|---|---|
| 新しい表(TripIntentDraft・DestinationCandidate)を作る | 仕様に無い DB の変更は利用者の判断が要る。既存の旅行・候補箱・preferences で足りる |
| 外部の AI で文章を読む | provider・鍵・個人の情報の外部への送信の判断が要る(未承認)。interface を足せば差し替えられる |
| 方面を地名の辞書から自動で提案する | 根拠の無い提案になる。利用者が挙げた方面だけを比べる |
| 運転時間を直線距離から推定して出す | 道路の実際と違い、確定値と誤解される。下限の判定だけに使う |

## 3. 未実装・制約

- 道路の経路・運転時間・高速料金、宿の在庫・料金、混み具合、方面の自動の提案、AI の読み取り(全て提供元が未接続)
- 家族での投票(候補箱の投票は FR-007 の gaps)
- 写真の場所の自動の特定(写真は段階3 の外部の写真・記録の写真で扱う)
