# ADR: データポータビリティ(FR-039)— 旅行単位・アカウント単位のエクスポートと保持期間の説明

- 状態: 採用(Gate P6)
- 前提: Gate P5(カレンダー・地図の書き出し)適用後
- 関連: DOC-02 FR-039 / FC-098 / §5 データ保持、DOC-04 SC-29、DOC-07 §13 バックアップ、DOC-11
- トレーサビリティ: `docs/trace/gate-p6-trace.md`

## 1. 背景

FR-039は「旅行の削除(B-012)」だけが実装済みで、エクスポートと保持期間の説明は無かった
(frontendにあった `exportData` はbackendのrouteが無く、Gate #27で削除済み)。

## 2. 決定

### 2.1 形式(FC-098 構造化JSON+文書manifest)

- `travelcanvas-export` v1。`format・version・scope・exported_at・requested_by・policy・retention` と、
  旅行ごとに `plan・tables(正本の表ごとの行)・counts・document_manifest` を持つ。
- 表の列はDBの列名・IDのまま出す(別システムへ移せるように)。UUID・日時は文字列、金額はDecimalの文字列。
- 応答に `X-Content-SHA256`(内容のSHA-256)を付け、画面に表示する(欠落・改ざんの確認用)。CORSで公開する。
- 「暗号化配布」(FC-098)は今回は行わない。代わりに、暗号化して保存している機密値をそもそも出さない(2.2)。

### 2.2 含めない情報

- 列名で一律に除外: 暗号文(`*_ciphertext`)・照合用ハッシュ・トークン・パスコード・保存キー・IPアドレス・メールアドレス。
  除外した列は `policy.omitted_fields` に表ごとに列挙する(黙って欠落させない)。
- 予約番号・PIN・名義・電話・チケットの中身は、アプリの開示機能(監査付き)で個別に確認する。
- 本人だけの情報(個人の持ち物・秘匿制約・個人予算)は、要求者本人の分だけを復号して出す。他人の分は行ごと出さない。
  他人の秘匿制約に関する検証結果も出さない。
- 匿名の投票では他人の回答を出さない。削除済みコメントの本文は出さない。
- 文書は原本ファイルではなく manifest(種類・分類・MIME・サイズ・SHA-256・ファイル名・作成日時)。

### 2.3 範囲と権限

- 旅行単位 `GET /plans/{id}/data-export`: 所有者だけ(他の参加者の作成物を含むため。403 `owner_only`)。
- アカウント単位 `GET /privacy/data-export`: 本人のプロフィール(本人のメールを含む)、所有する旅行すべて
  (削除後の猶予期間中のものを含む)、参加している旅行での本人の作成物(個人の持ち物・秘匿制約・個人予算・
  コメント・投票)、本人宛ての通知。
- 監査: `plan_data_exported`(表ごとの件数)・`account_data_exported`(旅行の件数)。内容は記録しない。

### 2.4 保持期間の説明(FR-039「バックアップ・監査の残存期間を説明する」)

- `GET /privacy/retention`: 削除の猶予日数(`PLAN_DELETE_GRACE_DAYS`)・下書きの保持日数は実際の設定値を返す。
  監査ログは「内容を含めず、セキュリティ上の保持期間」、バックアップは「運用環境の設定による(設計上の目安
  35日分と月次、DOC-07 §13)」と、アプリが制御していないことをそのまま説明する。書き出したファイル・印刷物は回収できない。

## 3. 今回の範囲外

- アカウント単位の削除、同意の撤回(同意の記録自体が未実装)、訂正の専用画面(各画面での編集で代替)。
- エクスポートの暗号化配布、非同期ジョブ化(大きな旅行での応答時間)、文書原本を含むアーカイブ(zip)。
