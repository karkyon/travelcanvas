# ADR: What-if・旅程ブランチ(FR-019)の最小実装

- 状態: 採用(Gate P7)
- 前提: Gate P6(データのエクスポート)適用後
- 関連: DOC-02 FR-019、DOC-04 SC-17、DOC-05 §7.6 itinerary_branches、共通不変条件4(差分・承認・Undo)
- トレーサビリティ: `docs/trace/gate-p7-trace.md`

## 1. 背景

FR-019(雨天・遅延・欠席・予算・体調などの分岐案を保存し、本案との差分と採用履歴を持つ)は全く無かった。
分岐案は本案を壊さないこと、採用は差分を見て承認したうえで1操作で戻せることが要件の中心である。

## 2. 決定

### 2.1 データ(migration `e6c1a9d3b7f2`、1テーブル新設のみ)

- `itinerary_branches`: 題名・想定(scenario_type・assumptions)・作成時点の本案の版(base_revision)と予定
  (base_snapshot)・分岐案の予定(content)・状態(draft/adopted/discarded)・採用した変更セット・revision・論理削除。
- 予定への外部キーは張らない(B-013の個別削除を妨げないため。採用時に存在を確認する)。plan_id は ON DELETE CASCADE。

### 2.2 想定による自動の案(branch-v1、`app/services/branches.py`)

- 遅延: 指定日の指定時刻以降の予定を N 分(15〜720)遅らせる。日付を越える予定は 23:59 に留めて注意を付ける。
- 雨天: 屋外の可能性がある予定(観光・アクティビティ)に注意を付ける。予定は外さない(判断は利用者)。
- 体力: 1日の予定数の上限(1〜10)を超える予定を、後ろから「外す候補」にする。
- 欠席・予算・自由: 予定はそのまま写し、想定のメモ(欠席する人・削減率)を持つ。
- 確定(ロック)した予定は自動では動かさない。自動の変更にはすべて理由のメモを付ける(説明できる案にする)。

### 2.3 採用(三方向の取り込み)

- 分岐案での変更 = base_snapshot → content の差分(追加・外す・項目の変更)。これを「現在の本案」へ当てる。
- 次の場合は409(`branch_conflict`)で止め、本案は変えない(黙って上書きしない):
  分岐後に本案でも同じ予定の同じ項目が別の値に変わった、本案で削除された予定を変更する、本案で確定された、
  予約・移動区間・経路候補・リンク・文書と紐付いた予定を外す、移動先の日程が無い。
  採用前でも詳細画面に同じ判定(採用できない理由)を表示する。
- 適用は1つの変更セット(source=branch)で記録し、本案の「元に戻す」で全て戻る。戻した後は案を「採用後に取り消し」と表示する。
- 開始日時(start_at)を持つ予定の時刻を変えた場合は、その日の新しい時刻へ合わせ、終了も同じだけずらす。

### 2.4 権限

- 閲覧はviewer以上、作成・編集・採用・見送り・削除はeditor以上。編集・採用・削除は分岐案のrevision(If-Match)。
- 監査は件数だけ(予定名・メモは記録しない)。

## 3. 今回の範囲外

- 予約・移動区間・費用の分岐(案に含めるのは予定だけ)、移動時間・制約違反・費用差の自動比較。
- 分岐案どうしの比較、本案の更新を分岐案へ自動で取り込む(rebase)機能。
