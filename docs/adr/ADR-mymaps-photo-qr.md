# ADR: マイマップ出力・写真の地図・QR の投稿(Gate MyMaps・PhotoMap・PhotoQR・PhotoPlace)

- 状態: 採用(2026-11-05。利用者が判断 1〜5 を確定)
- 関連: FR-036、FR-037、DOC-14 §4.5 MEMORY MAP・MAP-AC08、DOC-15 CA-012
- migration: `c4e8a2f6d1b3`

## 決定

1. **マイマップは案内付きの取り込み。** マイマップを作る公開の API を公式文書で確認できないため、KML を保存して本人が Google の画面で取り込む。TC は Google の認可もパスワードも扱わない。
2. **マイマップの位置の初期値は正確。** この画面だけ。宿泊場所は除外、守る範囲は常に除外。既存の GPX・KML 書き出しの初期値(約1km)は変えない。
3. **写真の位置の順序は 撮影位置 → 位置の記録 → 予定の時刻 → 手で置く。** スマホのブラウザは撮影位置を渡さないことがあるため。推定は `proposed` で保存し、本人が確定するまで本人以外に見せない。
4. **サーバーは撮影情報を保存しない(Gate Q1 のまま)。** 位置と時刻は端末で読み、フォームの値で送る。
5. **位置の公開は写真の公開と別(`location_visibility`、既定 private)。** 既存の記録にも適用する。
6. **位置の記録からの推定は約 100m に丸める。** 軌跡は暗号化だが `memories` の緯度経度は平文のため。本人の `synced` の軌跡だけを使う。
7. **QR だけでは投稿できない。** 認証は、旅行の編集者以上の会員のログイン、または発行者の PC に出る 6 桁のコード。コードの権限はこの QR の投稿 API にしか通らず、最長 12 時間。5 回間違えると QR を止めて発行者へ通知する。トークンとコードはハッシュだけ保存する。
8. **TC アカウントの無い同行者は対象外。** 必要なら後の段階で検討する。
9. **全クラスで開放。** 外部の有料 API を呼ばない。容量は既存の `upload_bytes` と 1 旅行 2,000 件の上限。
10. **縮小版は保存しない。** 要求の都度作る。削除の伝播を増やさないため。写真が多い旅行で遅ければ保存へ変える。

## 未確認・制限

- iPhone・Android の実機での位置と時刻の残り方。Google マイマップでの KML の Folder とレイヤの対応。
- 旅程の変更はマイマップへ反映されない。順路の線は地点間の直線。
- HEIC を直接は受け付けない(iPhone の Safari は JPEG へ変換して渡すとの報告あり)。撮影情報を読むのは JPEG だけ。
- マイマップのリンクは書き出し画面にだけ出す。ホーム・今日の画面への表示は未実装。
- 地図の印のまとめ表示(クラスタ)は未実装。
