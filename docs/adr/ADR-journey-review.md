# ADR: 旅の振り返り(FR-054 Plan-to-Memory・FR-053 旅の達成指標)の最小実装

- 状態: 採用(Gate P14)
- 前提: Gate P13(任意の位置軌跡)適用後
- 関連: DOC-02 FR-053/054、DOC-15 CA-011(Journey Completion Metrics)・CA-012(Plan-to-Memory変換)、DOC-04 SC-42 Journey Review、
  DOC-14 §4.4(到着/出発は手動・写真時刻等を根拠に提案し確定根拠を保持)、P12 旅の記録、P13 位置の軌跡
- トレーサビリティ: `docs/trace/gate-p14-trace.md`

## 1. 背景

予定(Plan)と実績(Actual)を区別して持つ仕組みが無く、旅行の後に「行った/行かなかった」「いつ着いて出たか」を残せなかった。
P12(記録)と P13(軌跡)で実績の材料はあるが、予定と結び付けて振り返る画面と指標が無かった。

## 2. 決定

### 2.1 データ(migration `d3f9b1c5e7a4`、1テーブル新設のみ)

- `event_actuals`: 予定1件に実績1件(uq plan_id+event_id)。状態(visited/skipped)、実際の到着・出発(UTC)、
  出どころ(manual/suggested)、メモ、記録した人、revision。予定(travel_events)は実績で上書きしない(CA-012)。
- 行かなかった予定に時刻を付けない・出発は到着以降をDBのCHECKで保証する。予定には外部キーを張らない(B-013)。
- 写真・メモ(memories)・軌跡は同じ予定ID(event_id)で結び付く(Candidate → Planned → Visited/Skipped → Memory の同一ID系列)。

### 2.2 実績の提案(journey-v1)

- 到着・出発の候補を、閲覧者本人の位置の軌跡(暗号化してサーバーへ保存したもの)で予定の場所から半径150m以内にいた
  最初と最後の時刻から出す。軌跡が無い・予定に位置が無い場合は、予定に紐付けた記録(本人・メンバー公開)の日時の最初と最後から出す。
- 提案は確定しない(利用者が「提案を使う」を押した時だけ記録し、出どころを suggested と残す)。時刻を記録した予定には提案しない。
- 他の人の軌跡・他の人の非公開の記録は、提案にも件数にも使わない。

### 2.3 予定と実績の比較・達成指標(CA-011)

- 予定の開始(日程のタイムゾーンの local_start_time)と実際の到着の差を分で示す(「予定より20分遅れ」)。
- 指標: 計画達成率(予定のうち行った)、訪問達成率(記録した予定のうち行った)、写真付き訪問率、記録完成率、
  記録のある予定の数、滞在時間(到着と出発がある予定の合計)、移動距離(本人の軌跡)。
- 分母が0の指標は null(画面は「—」)にし、0%と見せない。順位・他人との比較は作らない。数値は画面で隠せる(端末に覚える)。

### 2.4 行かなかった予定を次の旅行へ戻す(CA-012「行かなかった候補を次回旅行へ戻せる」)

- 行かなかった・未記録の予定を、利用者が編集できる別の旅行の日へ予定として作る(場所・種類・メモだけを写し、時刻・予約・確定・費用は写さない)。
- 戻し先の変更セット(source=carry_over)として記録し、戻し先の「元に戻す」で取り消せる。行った予定・同じ旅行は拒否する。

### 2.5 権限・書き出し・監査

- 振り返りの閲覧は viewer 以上、実績の記録・削除は editor 以上(旅行の共有データ)。戻すには戻し先の editor 以上が必要。
- 旅行の書き出しに `event_actuals` を含める。監査には状態・出どころだけを残し、予定名・メモを残さない。

## 3. 未実装(本Gateの範囲外)

- 予定ルートと実績ルートの地図での比較(TRACK MAP)、Geofence による到着・出発の自動検知
- 実績の変更履歴とUndo(変更セットへの記録)
- 次回計画への提案(CA-015 Memory Replan: 「美術館の実滞在が予定より平均40分長い」等)
- Personal Atlas(FR-052、訪問地域の集計)
