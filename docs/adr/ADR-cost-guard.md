# ADR: 外部 API の原価の守り(FR-059)

- 状態: 採用(Gate FR059-B、2026-10-29)
- 正本: `docs/spec/FR-059_旅程相談API原価上限_利用者クラス別Quota_v5.1.md`

## 決定

1. **予約してから呼ぶ。** provider を呼ぶ前に、価格の版から最大の見込み額を計算し、月 → 旅行の口座の行を `SELECT … FOR UPDATE`
   で押さえて予約する。予約を commit してから呼び(ネットワークの待ちの間に行を押さえない)、結果で確定か解放をする。
   既存の BILL-02(`usage_counters`)の1文の条件つき UPDATE では、回数・円・月の旅行の数を同時に確かめられないため、行の鍵にした。
2. **金額は Decimal(小数 4 桁)、見込みは切り上げ。** 表示は円の切り上げ。浮動小数点で円を計算しない。
3. **クラスは付与(entitlements)だけで決める。** `user_type`・画面の値・要求の本文は見ない。付与は二者の承認で active になる
   (DB の CHECK でも申請者と承認者を分ける)。
4. **有料の provider は `cost_guard.register_provider` で登録したものだけを `cost_guard.run` から呼ぶ。** 登録が無い間は
   「未接続(0円)」。価格が分からない・止められた provider は呼ばない(fail closed)。
5. **再試行は1回まで、二重の課金の恐れがある時は0回。** 期限(10分)を過ぎた予約は次の予約の前に解放する。

## 捨てた案

- クラウドの予算の通知だけで止める: 通知は遅れて届くため、1旅行の上限を守れない(正本 §9)。
- Redis だけで数える: 会計の記録(予約・確定・照合)を DB に残す必要があり、DB の行の鍵で十分に速い(1旅行の呼び出しは十数回)。

## 残り

- provider の停止の印は process の中(複数の worker で共有しない)。有料 provider を初めてつなぐ Gate で Redis へ移す。
- 無料の provider の使用の記録、組織でまとめる月の枠、指定した支払う人(決済 FR-058)。
