# ADR: 移動・滞在の既定・日をまたぐ予定・目的の内訳・案の比較・猶予つきの削除(Gate G7)

- 状態: 採用(Gate G7)
- 前提: Gate G6 適用後(Alembic `d7f1b5c9e2a6`)
- 関連: DOC-02 FR-005・FR-017・FR-018・FR-019・FR-039・FR-057、監査の実行台帳 MOVE-03・MOVE-04・MEM-03
- トレーサビリティ: `docs/trace/gate-g7-trace.md`

## 1. 背景

検証(FR-017)は終了時刻のある予定しか確かめられず、画面で作る予定の多く(開始だけ)は「検証できない」になっていた。
休憩・1日の長さ・最終の便は、利用者が制約を作らない限り確かめなかった。最適化(FR-018)は候補を丸ごと採用するしかなく、
何を良しとしたか(目的)が見えなかった。分岐(FR-019)は予定の差分だけで、移動・費用・予約への影響を比べられなかった。
予定の終了は日をまたげず、アカウントの削除はすぐの削除しか無かった。

## 2. 決定

### 2.1 データ(migration `e8b2c6d0f4a7`)
- `plan_movement_settings`(旅行ごとに1行): `settings`(JSON。歩く速さ・同行者・種類ごとの滞在・休憩・上限・最終の便の余裕)・`revision`(If-Match)。
- `travel_segments.last_departure_at`(最終の便。任意)。
- `users.deletion_requested_at`・`deletion_due_at`(両方あるか両方無いかの検査制約。予定日の部分索引)。
- 予定の終了は列を足さず `end_at`(UTC)を正本にし、画面には「現地の時刻」と「開始の日から何日後か(0〜2)」で見せる。

### 2.2 見積もり(feasibility-v2・movement-v1)
- 終了の無い予定は「種類ごとの既定の滞在 × 歩く速さの係数」で終わりを見積もる。見積もりで出た指摘は `estimated` を付け、
  エラーにしない(注意)。利用者が既定を「使わない」にすると以前の判定(v1 相当)に戻る。
- 休憩は「既定の分以上の空き」か「食事」。1日の上限・休憩なしの上限は歩く速さと同行者(子ども連れ・高齢の方)で短くする。
- 日ごとの疲れの目安は、活動の時間(種類の重み)・徒歩・乗り物の時間を、1日の上限に対する割合で示す(医学的な値ではなく目安)。
- 既定の版を検証の入力の指紋に含め、既定を変えたら以前の結果を古いと示す。

### 2.3 最適化の目的(MOVE-04)
- 目的は「移動距離・検証と制約(エラー10・守れていない制約5・注意2)・疲れ・公平さ」の重み付きの和。重みは 0〜5。
  重みを送った時だけ「条件に合わせた案」を足す(送らなければ以前と同じ候補)。
- 部分の採用は、候補の順のうち選んだ予定だけを動かし、他の予定の相対的な順を保つ(`optimizer.partial_order`)。
  確かめ(partial-preview)と適用は同じ計算で、入力の指紋と版が変わっていれば 409。

### 2.4 案の比較(FR-019)
- 本案と案(最大3つ)を同じ検証・同じ移動の見積もり(直線距離。移動区間があればその時間)で比べる。
- 外す予定に紐付く予約・費用は「外れる」として分けて示す。予約は自動で取り消さない(取消料は外部の判断)。
- 見せない設定(FR-045)の費用・予約は比較にも出さない(費用の合計から予約の有無を推測させない)。

### 2.5 猶予つきの削除(FR-039)
- 会員だけが申し込める(ゲストは即時の削除のみ)。申し込みの間はいつも通り使え、本人が取り消せる。
- 予定日を過ぎた申し込みは毎日の処理(`tcops.py jobs account-deletions`)が、すぐの削除と同じ手順で消す。管理者は飛ばす。

## 3. 採らなかったもの・残り
- 時刻表の照合・外部の経路の提供元による実移動時間(契約の判断待ち)。
- 案の中で予約・移動区間そのものを変える分岐(案の内容は予定だけ)。
- 所有者の移譲・出典つきの訂正(FR-039 の残り)。
