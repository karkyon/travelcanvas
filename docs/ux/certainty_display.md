# 確からしさの表示(設計と適用。Gate② UX P0。2026-11-20)

> 値を見た人が「どこから来た値か・信じてよいか」を、画面ごとに違う言葉でなく**同じ語彙**で分かるようにする。
> 競合比較レポート(2026-11-20)の P0「推定値/外部データの信頼表示を全画面で統一」と、DOC-13 §3(情報品質)・§16(当日の移動の出どころ)に対応する。

## 1. 状態の定義(共通の語彙)

正本: `frontend/src/components/common/certainty.ts`(`CertaintyKind`・`CERTAINTY_WORD`)。

| 状態(コード) | 語 | 意味 | DOC-13 §3 | 信じてよいか |
|---|---|---|---|---|
| `live` | 実データ | 提供元(API)から取った値。**取得時刻とともに**出す | IMPORTED / FRESH | よい(取得時刻つき) |
| `manual` | 手入力 | 利用者が入れた値 | USER_ENTERED | よい |
| `registered` | 登録した値 | 移動区間・経路の候補などに保存した値(当日の言い方は「登録した移動」) | USER_ENTERED | よい |
| `estimate` | 概算 | 距離や規則から計算した目安 | INFERRED | 確かめが要る |
| `unknown` | 不明 | 出どころが無い。**0 として扱わない** | — | 確かめが要る |
| `unqueried` | 未照会 | まだ提供元に聞いていない(聞けば分かる) | — | 確かめが要る |
| `unconnected` | 未接続 | 提供元がつながっていない(設定・契約が無い) | — | 確かめが要る |
| `failed` | 取得失敗 | 聞いたが取れなかった。**0 件と区別する** | UNAVAILABLE | 確かめが要る |

同義語の整理: 当日の「実時刻」は `live` の当日の言い方、「登録した移動」は `registered` の当日の言い方(画面の言い方は `word` で渡し、状態は共通)。DOC-13 §16 の「直線の目安」は地図の線の種類で、値の状態としては `estimate`。

## 2. 根拠(どこから状態を決めるか)

**画面の都合で「実データ」を付けない。** 状態は API の値から決める。

| 画面 | 値 | 状態を決めるデータ | 出典・取得時刻 |
|---|---|---|---|
| 当日(NOW/NEXT・出発の合図) | 次の予定までの移動時間 | `today guide` の `travel_source`(`provider`/`api`→live、`manual`、`segment`→registered、`estimate`、無し→unknown。`todaySource.sourceKind`) | 実時刻の提供元は今は無い(実際には live は出ない) |
| 旅行相談の場所の検索 | 結果の出典 | 応答の `retrieved_at` があれば live(無ければ unknown)。営業時間・料金は応答に無いので unqueried | 提供元の名前と取得時刻 |
| 全体の検索 | 検索そのもの | 応答が失敗 → `failed`。AI・有料の提供元 → `unconnected`(設定に無い) | 出典は結果ごとに「出典: …」 |
| 旅程の地図 | 区間の線 | `route-geometry` の `kind`(`road` は道に沿った経路、それ以外は直線の目安)。凡例は #156・#158 | 提供元 OSRM |

## 3. 共通の部品(`CertaintyBadge`)

- 文字(語)を必ず出す。1 文字の印(実・手・登・概・?・未・外・!)は `aria-hidden`。**色だけに頼らない**: 概算は点線の枠、不明・未照会は細い点線、取得失敗は二重線。
- 読み上げ: 語がそのまま読まれる。`title` に「出どころ: 語(時刻 取得)」。
- キーボード: 印は操作できる物ではない(フォーカスを取らない)。
- 狭い幅: `white-space: nowrap`・`max-width: 100%`。長い文は印の外に書く。
- 暗い表示: 背景と文字は画面の色(`--tc-cloud-50`・`--tc-ink-900`)、種類は枠の形と印の色で残す(`styles/certainty.css`)。
