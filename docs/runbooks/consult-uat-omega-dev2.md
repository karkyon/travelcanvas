# 旅行相談の UAT(omega-dev2 / 192.168.1.11)— 実 AI・文字と音声

目的: 行き先が決まっていない利用者が、文字または音声で取り留めのない希望を伝え、AI がカテゴリ別に整理し、
利用者が確認・訂正して旅行計画(下書き)へ進めること。

- 実 AI の UAT は、運用コンソールの概要「旅行相談の UAT の準備(このアカウント)」が **「実 AI で相談できます」** の時だけ行う。
  足りない項目は、その表の「変える場所」で直す(登録済みの鍵は再入力しない。確認済みで期限内の鍵は確認し直さない)。
- 模擬(`PROVIDER_HTTP_STUB`)の結果は実 AI の結果として記録しない。結果は「実 API」と「模擬」を分けて書く。
- 鍵の値・相談の本文(個人の事情)を報告・Issue・チャットに貼らない。

## 0. 準備(運用者)

| 何を | どこで | 合格 |
|---|---|---|
| 反映の SHA・DB の revision | `git -C ~/projects/travelcanvas rev-parse HEAD`・`docker compose exec -T backend alembic current` | main の SHA・`head` |
| UAT の準備 | `/admin/ops` › 概要 › 旅行相談の UAT の準備 | 全行 OK(会員クラス Journey 以上・AI の利用の同意・3つの操作「使える」・送り先「実の提供元」) |
| 鍵の表示 | `/admin/ops` › 秘密情報・権限 | OpenAI・Google サーバー用が「登録済み・接続確認済み」と確認期限。ブラウザ用は「現在の構成では使用しません。設定不要」 |
| 音声の入口 | `bash scripts/ops/uat_https.sh up`(1回)→ 端末に証明書(下の 0-a) | `OK: https の入口 https://192.168.1.11:4443/trip-consult` |

会員クラスの切り替え(開発環境・24時間・監査に残る): `/admin/ops` › 会員クラス › 試験のためにクラスを切り替える。
同意: 旅行相談の画面の「AI で読み取る」の枠の同意の印(設定 › プライバシー で撤回できる)。

### 0-a. 音声の UAT の端末(https)

`http://192.168.1.11:4173` はブラウザが安全な接続と見なさないため、マイク・音声認識を使わせない(画面に理由が出る)。
音声の UAT は `https://192.168.1.11:4443` で行う(caddy の内部 CA。開発の UAT だけ)。

1. omega-dev2: `cd ~/projects/travelcanvas && bash scripts/ops/uat_https.sh up`
   (`.env` の TC_UAT_* と TC_PUBLIC_HOSTS の行だけを足し、backend・frontend を作り直し、証明書・health・ready・画面・CSP・CORS を確かめる)
2. 端末で `http://192.168.1.11:4480/travelcanvas-uat-root.crt` を開いて保存し、出力された SHA-256 指紋と同じか確かめて入れる
   (Windows・Android・iPhone の手順はスクリプトの出力)。
3. `https://192.168.1.11:4443/trip-consult` を開き、「音声で入力」に「録音を始める」が出る(理由の文が出たら証明書・ブラウザを確かめる)。
4. 終わったら `bash scripts/ops/uat_https.sh stop`、端末から証明書を消す。

## 1. 入力例

最初の相談(文字・音声のどちらでも):

> 大阪から大人4人、車で1泊2日。行き先はまだ決まっていない。片道3時間以内。静かな景色のいい場所がいい。
> 市場や地元の食べ物も楽しみたい。予算は4人分の旅行全体で8万円以内。激しい運動はしない。

追加・訂正(確認の画面の「追加で伝える・変える」):

> やっぱり人数は3人。予算8万円は宿泊代だけに変更。市場は絶対ではなく、行けたらでいい。

## 2. シナリオ(実環境・実 AI)

各行に「合否・端末(PC/スマートフォン)・入口(http/https)・実 API か模擬か・証拠(画面の写し・原価の台帳の行)」を残す。

| ID | 操作 | 合格の条件 | 見る所 |
|---|---|---|---|
| U01 | 行き先未定のまま `/trip-consult` を開く | 「入力の仕方」(AI に自由に相談 / 項目ごとに入力)と、文字の欄・「音声で入力」が迷わず分かる | 相談の画面の上 |
| U02 | 1 の最初の相談を入れて「AI で読み取る」(1回) | 出発地・方面・人数・日程・目的(過ごし方)・予算・やりたいこと等に分かれ、AI の行は「AI の読み取り · 未確認」 | 確認の画面 |
| U03 | 「静かな場所がいい。市場も見たい」を追加で伝える(AI で反映) | 元の希望が残り、追加分が分かる(確かめた行は消えない) | 確認の画面・その他の希望 |
| U04 | 「4人ではなく3人」と訂正 | 人数に「変更案(4 → 3)」が出て、採用するまで確かめた値は変わらない | 変更案の枠 |
| U05 | 矛盾する希望(例「日帰りで1泊したい」)を入れる | 勝手に片方へ寄せず、確認事項(質問)として示す | 確認事項 |
| U06 | 項目に収まらない希望(例「何もしない時間もほしい」) | 「その他の希望」に残り、直す・消すができる | その他の希望 |
| U07 | 「4人分・旅行全体・8万円以内」 | 予算は誰の分=全員の合計・対象=旅行全体・上限。宿泊費として扱わない。2 の訂正で対象=宿泊費の変更案 | 予算の行 |
| U08 | 「項目ごとに入力」で AI を使わずに入れる | AI なしで確認・下書きへ進める | 確認の画面 → 下書き |
| U09 | 「直前の変更を元に戻す」 | 直前の追加・訂正だけが戻り、他の確かめた内容は残る | 確認の画面 |
| U10 | 確認後「この条件で方面を比較する」→ 下書き | 確かめた条件とその他の希望が下書きへ引き継がれる。確かめていない日数・出発地は使われない | 方面の比較・下書き |
| U11 | https の入口で音声入力 → 停止 → 文字起こしを直す →「相談に追加」 | 停止しても自動で送らない。直した文が相談に足される。マイクの許可を確かめる | 音声で入力 |
| U12 | 通信を切って送る・連打・再試行 | 入力が消えない。二重に送らない・二重に数えない(原価の台帳の行が1回分) | 画面・原価の台帳 |

## 3. 実 API と利用台帳の照合

1. UAT の前後に `/admin/ops` › 原価・利用台帳 と概要の「今月の実の提供元の見込み」を記録する。
2. 実 AI の呼び出し(U02・U03・U04・U07)の回数と、台帳の openai の確定の件数・額が合う(Journey は 1相談 3回まで・1旅行 50円まで)。
3. 同じ操作の連打・再試行(U12)で件数が増えない。
4. OpenAI・Google の請求の画面の値との照合は、明細が出てから(アプリの額は見込み)。
