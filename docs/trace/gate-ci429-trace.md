### 原因の訂正(2回目の commit の CI)

更新を同時に1本にした後の CI(job 123444965414・123445763564)でも、2 run とも遮断の前の実際の点数は同じ(合計 210・`rate_limited /api/v1/auth/refresh` 123)で 50 件が 429 になった。**同時の 401 は原因ではなかった**(直しは無駄な更新を減らす改善として残す)。

サンドボックスの access log を会員の登録ごとに区切って数えると、更新(`POST /auth/refresh`、全て 200)が最も多いのは段階4 の `gate-g11-style.spec.ts`(53回)。この試験は 4系統 × 明暗 × 2幅 × 3画面 = 48回 `page.goto`(読み直し)し、会員は読み直しのたびに cookie の更新鍵でアクセストークンを取り直す。CI の速さでは1分 60回(`RATE_LIMIT_REFRESH`)を越え、越えた分の 429 が 3点ずつ積もって 150 で遮断 → 後の全ての試験が 429。**連鎖が段階4(PR #13)から始まったことと合う。**

直し: この試験の画面の移動を、読み直さない画面の中の移動(`history.pushState` + `popstate`。利用者のリンクの操作と同じ)にし、読み直しは系統・明暗の組ごとに1回にした(更新は 53回 → 18回)。閾値・点数の付け方・E2E の再試行は変えない。
